# 调研：HuC6280（PC Engine PSG）的波形可视化

**状态**：调研完成，未改代码
**测试文件**：`test_file/HuC6280/01 Magical Sound Shower.vgz` … `04 Last Wave.vgz`（OutRun，4 首）
**相关**：`docs/desgin/libvgm-visualisation.md` §9、`chips/HuC6280Decoder.cpp`、`emu/cores/c6280_mame.c`

---

## 1. 结论

这一颗**不是采样芯片，是波表芯片**：6 个通道，每个通道 32 个 5 bit 波形点 + 12 bit 分频。
所以“实现”的内容和 DAC/Y8950 完全不同：

1. 把每通道的 32 点波形从寄存器流里解出来，交给行去画（**现在画的是占位形状**）；
2. 速率 = `clock / max(f, 1)`，即波表被逐点走过的速度；
3. 噪声通道（4/5）单独给一个形状；
4. **DDA（采样流）这四首里没有实际使用**，可以不做，写清楚边界即可。

工作量约 **120 行**（解码器为主）+ 断言，不需要动 `SongIr`、不需要动 MIDI。

---

## 2. 现状（实测）

`01 Magical Sound Shower` 在键盘页的情况：

- 行是**有的**：6 行，名字 `Ch 1..Ch 6`，音符 A0/A3/A2/E3/–/C2 正常；
- 每行的形状是**同一个占位图形**——`channelState()` 从不填 `wave`，而 `ChannelKind::c6280Wave` 属于
  `Kind::stored`，没有形状时画占位（`ChannelFromChip.cpp` 的注释写明“画占位而不是撒谎”）；
- `assert engine wave.0` 返回 **0**（`was: 0 of 6 channels`），确认快照里没有波形；
- 右上 “Export wavetables” 目前无内容可导。

解码器本身是好的：`HuC6280Decoder` 已经处理 `0x00`/`0x02`/`0x03`/`0x04`/`0x07`，音符与鼓键都正确；
缺的只有 **`0x06` 波形数据** 和 **DDA 的状态**。

## 3. 芯片模型（以 `c6280_mame.c` 为准）

寄存器只有 10 个，`0xB9 aa dd`，`aa` 的低 4 位是寄存器、高 4 位是 port：

| 寄存器 | 含义 |
|---|---|
| `0x00` | 通道选择（低 3 位），后续写作用于该通道 |
| `0x01` | 全局音量/平衡（只影响左右） |
| `0x02/0x03` | 频率，低 8 位 + 高 4 位 |
| `0x04` | 控制：bit7 key-on、bit6 **DDA**、bit4-0 音量 |
| `0x05` | 通道平衡 |
| `0x06` | **波形数据**（5 bit）：DDA 关时写波表，DDA 开时写 DDA 电平 |
| `0x07` | 噪声：bit7 开、bit4-0 频率 |
| `0x08/0x09` | LFO（只调制 ch0，未建模） |

### 3.1 波表与索引

- 每个通道 `waveform[32]`，`index` **只在通道未 key-on 时自增**（核心 `c6280_mame.c:236-244`）；
- `0x04` 的 DDA 位 **1→0** 时 `index = 0`；
- key-on 只重置计数器，不重置 `index`。

> 所以“驱动写 32 个字节”通常发生在**关音**时；写完后 key-on，表就是最终形状。这决定了解析器必须
> 照抄 `index` 的规则，否则画出来的表会错位。

### 3.2 速率

核心的 `wave_freq_tab` 是 `((clk/rate) * 4096) / (i+1)`，`i+1 = f`；计数器每跨 4096 推进一步。于是

```
每秒步数 = clock / f        （f = 0 时按 4096 处理）
音高     = clock / (32 * f)
```

这与 `HuC6280Decoder` 现有的音高表（`clock / (32 * divider)`，`divider = f ? f : 4096`）互相印证。
行需要的 `sampleRate` 就是**每秒步数** `clock / f`。

### 3.3 噪声

ch4/ch5 可切到 LFSR（`0x07` bit7）。现有解码器已按鼓键处理，`isDrum` 正确；行目前仍画占位。

### 3.4 DDA

`0x04` bit6 打开后，`0x06` 写的是**采样电平**，由 CPU 按自己的节奏喂，像 YM2612 的 DAC。
这四首里 DDA 只出现在**初始化**（先把 6 个通道置 `0x40` 再置 `0x00`），**没有任何 DDA 字节**，
所以不是本次的必做项。

| 02 Passing Breeze | — | 293 735 | 5 697 | 32 / 91 / 91 / 91 / 111 / 32 | 0 |
| 03 Splash Wave | — | 352 509 | 7 025 | 32 / 32 / 61 / 32 / 111 / 32 | 0 |
| 04 Last Wave | 2.1 s | 26 765 | 521 | 64 / 64 / 63 / 64 / 64 / 32 | 0 |

- 所有文件的 **HuC6280 时钟字段都是 0**（header 0x6D 与 0x6C 都是 0），所以解码器用默认
  **3 579 545 Hz**；这与 PC Engine 的 PSG 时钟一致，暂不需要额外处理；
- 每通道只有 **1–3 张不同的表**（32 槽 = 一张表），缓存会非常小；
- 实际波形是真正的 5 bit 形状（例如 ch2 是一条 0→31 的锯齿，ch4 是噪声包络），不是随机字节。

```

ch2   0  0  1  2  3  5  6  7  9 10 11 13 16 20 25 31  6  9 11 13 15 17 18 20 22 23 24 26 27 28 30 31
```

## 5. 方案

### A. 解码器暴露波形（必做）

`HuC6280Decoder::Impl::Channel` 增加：

```cpp
uint8_t waveform[32] = {};
uint8_t index = 0;
```

`write()` 的 `0x06` 分支照抄核心：DDA 关时写 `waveform[index] = value & 0x1F`，并在 `!(control & 0x80)`
时 `index = (index + 1) & 0x1F`；`0x04` 检测 DDA 1→0 时 `index = 0`。

`channelState()`：

```cpp
state.wave      = waveForChannel (channel);   // 32 点，-1.0 .. +0.9375，中心 0x10
state.tableWave = true;                        // 一个周期，不是录音
state.sampleRate = clock / (f ? f : 4096);     // 每秒步数
```

缓存：32 字节内容 hash → `shared_ptr<const std::vector<float>>`，沿用 `K005289Decoder` 的
`waveCache` 写法（`std::map<uint64_t, ...>`，上限 64 张；`reset()` 清空）。驱动每帧最多写一张表，
`channelState` 又被每帧调用 6 次，所以解码必须命中缓存，不能每次都分配。

### B. 噪声行（建议做）

新增 `ChannelKind::c6280Noise`（与 `wsNoise`/`sn76489Noise` 同级），`channelKind()` 在
`channel >= channel4 && (noiseControl & 0x80)` 时返回它，`waveKindForChannelKind()` 映射到
`Kind::noise`。这样 ch4/ch5 一开噪声，行就从“波形”变成“噪声”，与 SN76489/WonderSwan 一致。

### C. DDA（建议本次不做）

要做的话是另一套模型：DDA 字节是**流**，边界和速率只能按写入时间测（和 YM2612 DAC 同类问题），
而这四首完全没有用到。建议：`0x06` 在 DDA 开时只更新 `dda` 电平、行维持“静音/占位”，在头注释里
写明边界（现有注释已经这么写了），等有实际用到 DDA 的文件再说。

## 6. 边界与风险

1. **索引语义**：不做 `index` 就会被“关音时写表”的驱动画错位；这是本次最容易错的一处。
2. **时钟为 0**：四首都是 0，解码器回落到 3 579 545；若某首写了非零时钟，按实际值算速率即可。
3. **占位形状**：改动后每行的占位图形会被真实表替换；`Export wavetables` 也会随之有内容
   （`tableWave` 走 `nearest()` 铺到 2048 点，与波表导出的既有规则一致）。
4. **性能**：429k 条写入已经能正常加载；新增开销只有“每帧每通道一次缓存查找”，可忽略。
5. **MIDI 不变**：音符已经由现有解码器给出，本次只动显示与导出用的 `wave`。
6. **LFO 不建模**：它只调制 ch0 频率，不影响形状；如需要以后再单独做（与本次无关）。

## 9. 已实现（2026-11-11）

按方案 A + B 落地：`0x06` 的 32 步表进入解码器（索引规则照抄 `c6280_mame.c`），`channelState` 填
`wave`/`tableWave`/`sampleRate = clock / f`，按 32 字节 hash 缓存；噪声通道改用新增的
`ChannelKind::c6280Noise`。DDA 仍不建模（四首测试曲目没有实际使用），注释写明边界。

实测：四首都能画出每行各自的表（`assert engine wave.N == 32`），键盘页从占位图形变成真实波形，
“Export wavetables” 随之可用；`testC6280WaveTable` / `testC6280WaveIndex` / `testC6280NoiseKind`
三条断言钉住缩放、索引与噪声类型。
