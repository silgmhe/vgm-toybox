# 调研：8 位采样拖进 DAW 为什么变“闷”

> 背景：用户把导出的 DAC 采样拖进 32 位浮点工程，听感比 Furnace 里播放**少了一层高频细节**，阶梯感消失。
> 目的：先定位是哪一步丢的，再决定导出要不要改。**本文只做分析，不改代码。**
> 结论先行：**丢在重采样，不在位深。** 文件按实测速率（8–23 kHz）导出，DAW 导入时把它重采样到工程速率，带限到文件的 Nyquist（23 kHz 文件只剩 11.5 kHz），而“阶梯感”恰恰是零阶保持的**镜像**（23 kHz ± f）——它们落在文件带宽之外，任何忠实的重采样都会把它们滤掉。

---

## 1. 五条结论

1. **32 位容器不是原因。** 位深从 8 位到 32 位浮点是精确的（8 位只有 256 个电平，浮点能原样表示）；我们的 WAV 本来就是 float32（`WaveExport.cpp:110-136`）。用户听到的“8 位”是**电平网格**，不是容器。
2. **原因是速率不匹配。** 文件头写的是实测速率（DAC 是 8–23 kHz，Y8950 ADPCM 15.9 kHz，Delta-T 13.9 kHz），DAW 工程是 44.1/48 kHz，导入即重采样。文件采样率 23 105 Hz 的 Nyquist 是 11.55 kHz，之上的一切在导入那一刻就没了。
3. **“阶梯感”不在文件里，是播放时保持出来的。** 我们在文件里写的是**每字节一个点**；芯片播放时把这个点保持到下一次写，形成零阶保持。它的频谱是 `sin(πf/rate)/(πf/rate)` 乘以一串位于 `rate × k ± f` 的镜像——这些镜像正是听感里的“颗粒/高频”。文件里没有保持，所以也没有镜像。
4. **Furnace 之所以有，是因为它不做带限重采样**：样本按自己的速率逐点读出，输出端用保持（插值关）而不是先低通再插值，于是镜像被搬进输出流。DAW 走的是“先带限到文件 Nyquist，再插值”，两者对同一份字节的处理不同。
5. **我们其实已经解决过一次同类问题**：波表导出用 `nearest()` 把一个 32 点周期**铺成 2048 点、44.1 kHz**（`WaveExport.cpp:35-60`），注释里写的就是“深度属于纵轴，保持属于横轴”。**采样导出没有用这条规则**（`writeSampleWav` 直接按 `channel.sampleRate` 写）。

---

## 2. 实测：三种处理，同一段字节

`02 Green Hill Zone` 的三段，指标如下（`flat%` = 相邻相等样本的比例，即阶梯平台；`|dx|` = 一阶差分 RMS，高频能量的粗糙代理；`HF` = 两次一阶高通（截止 = 速率/4）后的 RMS 与总 RMS 之比）：

| 段落 | 处理 | 长度 | flat% | \|dx\| | HF |
|---|---|---|---|---|---|
| 0x0000 @14 783 | 原样（芯片速率） | 5 398 | 0.113 | 0.0956 | 0.024 |
| | 线性插值 → 44.1k | 16 103 | 0.090 | **0.0302** | **0.005** |
| | 最近邻保持 → 44.1k | 16 103 | **0.703** | **0.0553** | **0.013** |
| 0x1516 @23 105 | 原样 | 3 810 | 0.050 | 0.1071 | 0.030 |
| | 线性插值 → 44.1k | 7 272 | 0.025 | **0.0511** | **0.012** |
| | 最近邻保持 → 44.1k | 7 272 | **0.502** | **0.0775** | **0.021** |
| 0x0060 @7 981 | 原样 | 1 488 | 0.258 | 0.0224 | 0.005 |
| | 线性插值 → 44.1k | 8 222 | 0.235 | **0.0040** | **0.000** |
| | 最近邻保持 → 44.1k | 8 222 | **0.866** | **0.0095** | **0.002** |

读法：

- **线性插值把高频削掉 6–20 dB**（23 kHz 段 `|dx|` 从 0.107 降到 0.051，`HF` 从 0.030 降到 0.012）；真正的 DAW 用 sinc，削得比线性更多，所以这是**保守估计**；
- 保持版保留了 **50–87% 的平台**（原样文件只有 5–26%，因为它每字节一个点，没有平台），`|dx|`、`HF` 都比插值版高一档；
- 8 kHz 那段最极端：线性插值后 `HF` 几乎归零——听感就是“闷掉了”。

## 3. 一条时间轴讲清

```
驱动写字节（8–23 kHz）
   │
   ├─ 芯片：把电平保持到下一次写 ──► 阶梯 ──► 频谱含 rate×k ± f 的镜像 ──► 听感“颗粒”
   │
   └─ 我们导出：每个字节一个点，文件速率 = rate
        │
        ├─ DAW 导入（工程 44.1/48k）：先低通到 rate/2，再插值
        │     └─ 镜像全被滤掉 ──► 平滑 ──► 听感“闷”
        │
        └─ 若导出时在目标速率上做保持：文件里就是阶梯
              └─ DAW 1:1 播放（速率相同，不重采样）──► 阶梯还在 ──► 听感不变
```

关键数字：文件 23 105 Hz 的 Nyquist 是 **11.55 kHz**；阶梯的镜像在 **23.1 kHz 附近**，两者差一个八度。所以这不是“DAW 不好”，而是**文件格式装不下**——除非把保持烘进更高采样率的文件。

---

## 4. 与波表导出的对照（同一规则，只用了一半）

`WaveExport.cpp` 里已经有一条明确的规则，注释写得很清楚：

> 深度属于纵轴，保持属于横轴，两者互不决定。插值试过两次，每次都把 32 级阶梯变成平滑斜坡——硬件从不产生那个形状。

波表路径按它做了：一个周期用 `nearest()` 铺到 **2048 点、44 100 Hz**（`writeCycleWav`，`kWavetableRate = 44100`、`kWavetableSamples = 2048`）。采样路径没有：`writeSampleWav` 直接 `writeFloat32Wav(path, values, lround(channel.sampleRate))`，把“保持”留给播放端。

**同一规则应当覆盖采样导出的横轴**：文件速率取目标速率、每字节保持整数个采样点。

---

## 5. 方案

### A. 导出时按目标速率做零阶保持（推荐）

```
n = round(len * target / rate)          // 输出点数
out[i] = in[(i * len) / n]              // 整数除法 = 零阶保持
WAV 头写 target
```

- 与波表路径同一个 `nearest()`，代码只有几行；
- 目标速率 = **DAW 工程速率**时，导入后 1:1 播放，阶梯完整保留；
- 文件变大：14.8k → 44.1k 是 3.0×，23.1k → 44.1k 是 1.9×，8k → 44.1k 是 5.5×。

**目标速率从哪来**（这是要定的）：

| 运行形态 | 建议取值 |
|---|---|
| 插件（跑在 DAW 里） | **宿主采样率**（引擎已有 `deviceRate` / 宿主回调速率） |
| 独立版 | 输出设备速率；没有设备时 44 100 |
| 设置项 | `跟随宿主 / 44 100 / 48 000 / 96 000 / 芯片速率`，默认“跟随宿主” |

如果目标速率与工程速率仍不同（例如设置了 44.1 而工程是 48k），DAW 会再重采样一次，阶梯又会被削——所以**默认必须是“跟随宿主”**，固定值只用于“导出去给别人用”。

### B. 保持现状（芯片速率）

不改变文件，只在文档/提示里说明“DAW 会重采样”。优点：文件小、速率是“真相”；缺点：用户听到的就是现在这个“闷”的结果。

### C. 双份

同一段字节写两个文件：`name.wav`（芯片速率，给人/给 tracker）与 `name@44k.wav`（保持，给 DAW）。优点：两种用途都在；缺点：文件数量翻倍、名字变长。

### D. 改音色（不推荐）

导出时做抗镜像、抖动或轻微饱和来“补”高频。这会把不属于硬件的成分加进去，和 `nearest` 注释里反对插值的理由冲突。

---

## 6. 影响面与副作用

- **受益的是所有“采样”类通道**：YM2612 DAC、Y8950 Delta-T、OPN ADPCM-A/B、SegaPCM、C64、K053260…它们的速率都在 4–32 kHz，全都会被 DAW 重采样。
- **拖拽导出**（`writeSampleWav`）与**批量导出**（`writeSamples`）是两条路径，要一起改，否则同一段字节在两种用法下听感不同。
- **面板上的行不受影响**：行是画形状，与文件无关。
- **16/24 位整数容器**要不要提供是另一件事：位深不参与本次问题，改成 16 位不会让阶梯回来，也不会让阶梯消失。
- **芯片速率仍要保留在元数据里**：将来若要做“按原速播放的 tracker 素材”，芯片速率才是正确的 header。建议文件名或注释保留原速率（例如 `@14k` 后缀），或用 `clm`/`LIST` 记录。

## 8. 附：本次用到的测量口径

- 数据来源：`02 Green Hill Zone` 的 PCM bank，`0x0000`（5 398 B）、`0x1516`（3 810 B）、`0x0060`（1 488 B），已按有符号转换；
- “线性插值”= 目标点上按 `pos = i × rate / target` 取相邻两点线性混合（多数 DAW 的“低质量”档，sinc 会更平滑）；
- “最近邻保持”= `out[i] = in[(i × len) / n]`，与 `nearest()` 同一算法；
- `HF` = 两级一阶高通（截止 `rate/4`）后的 RMS ÷ 原 RMS，只用于横向比较，不是绝对频谱。

## 9. 已实现（2026-11-10）

按方案 A 落地：

- `WaveExport.cpp` 新增 `heldAt()`（零阶保持，与波表 `nearest()` 同一规则）；`writeSamples()` 与
  `writeSampleWav()` 接受 `targetRate`，0 表示保持芯片速率；`writeChannelShape()` 透传；
- 设置 `export.sampleRate`：`0` 跟随宿主（默认）、`-1` 芯片速率、`44100/48000/96000` 固定；
  `SettingsStore::getExportSampleRateHz(hostRate)` 负责解析，插件用 `processor.getSampleRate()`，
  独立版用 `PlaybackEngine::outputSampleRate()`；
- 两条导出路径都走它：`PluginEditor`（File > Export）与 `ContentSlot`（拖拽）；
- 导出设置页新增下拉框（`settings.export.sampleRate`），中英文案已补。

验证：`NsfFormatTest` 钉住保持后的文件长度与头部速率，并单独验证 `writeSampleWav` 的拖拽路径；
`settings-pages.txt` 钉住下拉框默认值与三个选项；`49/49`、芯片与 NSF 断言全过。
