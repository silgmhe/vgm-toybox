# 调研：X1-010 的波表与 PCM 可视化

**状态**：调研完成，未改代码
**测试文件**：`test_file/X1-010/` 十三首（Daiou? 1993 年 Seta 作品，见 GD3）
**相关**：`chips/X1_010Decoder.cpp`、`emu/cores/x1_010.c`、`docs/desgin/libvgm-visualisation.md` §9.1

---

## 1. 结论

X1-010 是**一颗芯片里两套乐器**：16 个通道，每个通道由状态位 bit1 选择

- **PCM 模式**：从 1 MB 采样 ROM 里按 start/end 播放 8 位有符号样本（鼓、语音）；
- **波形模式**：从芯片内的 4 KB 波形 RAM 里播 32 张 128 字节的表（旋律）。

所以“可视化”要同时做两件事：**PCM 行显示正在播的样本**，**波形行显示当前那张表**。两者的
`state.wave` 相同，但 `tableWave` 不同（前者是录音，后者是一个周期）。

此外有两个已有问题必须一并修正：

1. 解码器**忽略 `0x04/0x05`（start/end）**，注释里写着“寄存器里没有样本结束位置”——**这是错的**，
   `0x05` 就是结束地址；
2. PCM 的 gate 因此是固定 80 ms；有了 start/end 与速率就能算出真实时长。

---

## 2. 现状（实测）

`02 Stage 1` 的键盘页：**16 行**，PCM 通道显示 `C3`（鼓键），波形通道显示 `C0`（音高），
所有行都是同一个占位横线，`engine.wave.0 == 0`，“Export wavetables” 无内容。

解码器已经正确处理的：状态位（key / PCM-waveform / divider）、音量、频率/音高、PCM 的一次性 gate、
`channelKind`（`x1Wave` / `adpcmDrum`）。缺的是**波形 RAM**、**ROM** 和 **start/end**。

## 3. 芯片模型（`x1_010.c`）

### 3.1 寄存器（每通道 8 个，通道 `n` 在 `8 * n`）

| 寄存器 | PCM 模式 | 波形模式 |
|---|---|---|
| 0 状态 | bit0 key、bit1 模式（0=PCM）、bit7 分频 | 同左，bit2 = 包络一次性 |
| 1 音量 | L/R 各 4 位 | **波形号**（0..31） |
| 2 | PCM 频率 | 音高低 8 位 |
| 3 | — | 音高高 6 位（14 位 6.10） |
| 4 | **start / 0x1000** | 包络时间 |
| 5 | **end = (0x100 − 值) × 0x1000** | 包络号 |
| 6/7 | 保留 | 保留 |

`div = 状态 bit7 ? 1 : 0`，频率与音高都要右移 `div`。

### 3.2 内存映射（写入通过 `0xC8` 的 16 位 offset）

| 区间 | 内容 | 测试文件里的写入量 |
|---|---|---|
| `0x0000-0x007F` | 通道寄存器 | 1.9k–36k 次 |
| `0x0080-0x0FFF` | 包络 RAM（16 张 × 128 字节） | **2 048 次/首**（一次性上传） |
| `0x1000-0x1FFF` | 波形 RAM（32 张 × 128 字节） | **4 096 次/首**（一次性上传） |

波形 RAM 是**静态的**：每首歌开头写满 4 KB，之后不再改。

### 3.3 PCM 的速率与长度

```
start = reg4 × 0x1000
end   = (0x100 − reg5) × 0x1000          // 两者都是以 4 KB 为单位
rate  = clock / 8192 × freq              // freq = reg2 >> div；core 对 freq == 0 用 4
长度  = (end − start) 字节 / rate 秒
```

核心在 `delta ≥ end` 时自动 key off——**所以真实时长是可算的**，不需要 80 ms 的近似。

### 3.4 波形模式的速率

```
pitch   = ((reg3 << 8) | reg2) >> div            // 14 位 6.10
步进率  = clock × pitch / 524288                 // 核心 step 的化简
周期    = 步进率 / 128                           // 一个波形 128 步
```

与现有 `X1NoteTable` 的 `clock × period / 2^26` 完全一致（`2^26 = 128 × 524288`）。

## 4. 测试文件实测（前四首）

| 项 | 结果 |
|---|---|
| 时钟（header 0xD8） | **16 000 000**（与解码器默认一致） |
| ROM 块 | 类型 **0x91**，声明大小 **1 MB**，按 offset 放置（每首 2–5 块） |
| 波形 RAM 上传 | 每首 **4 096** 字节（32 张表，一次性） |
| 包络 RAM 上传 | 每首 **2 048** 字节（16 张，一次性） |
| 模式分布 | 两首都用；PCM key-on 1 515–4 272 次，波形 437–2 569 次 |
| PCM 样本长度 | 8 192 / 28 672 / 65 536 字节为主；`01 Intro` 有一次 **1 048 576**（整块 ROM） |
| PCM 频率 | 0、16、17、21、22、25、30、34、35、38、42、43 → 速率约 0–84 kHz |
| 波形音高 | 120–736（23–59 个不同值）→ 步进率 3.6k–22.5k |

## 5. 方案

### A. 解码器（必做）

1. `kRequirements` 补内存：`{ 16000000u, true, 0x91, 1u << 20, false, false }` + `attachMemory`；
2. 保存波形 RAM：`int8_t waveRam[32][128]`，来自 `offset 0x1000-0x1FFF`
   （`channel = (offset - 0x1000) >> 7`，`step = offset & 0x7F`）；包络 RAM 不保存（不影响形状）；
3. `channelState`：
   - **PCM**：`wave` = `rom[start..end)` 解码成 `/128`，`tableWave = false`，
     `sampleRate = clock / 8192 × max(freq, 4)`；gate 用 `now < startTime + length/rate`；
   - **波形**：`wave` = `waveRam[waveNo]`（128 点，`/128`），`tableWave = true`，
     `sampleRate = clock × pitch / 524288`；
4. 缓存：PCM 按 `(start, length)`，波形按 32 张表的内容或索引；上限沿用既有写法。

### B. 选项：PCM 导出收集器（`collectX1010Samples`）

与 `collectC140Samples` 同一形状：扫 `0xC8`，在 key-on 边沿记下 `(start, end, freq)`，
按 `(start, length)` 去重、首次速率胜出，输出 8 位有符号 WAV。名字建议
`x1010_%06X_%05X`（本 ROM 最大 1 MB，6 位十六进制够）。

### C. 不做

- 包络 RAM 与音量包络（只影响响度）；
- 波形模式的一次性/重复标志对“形状”的影响（只影响 gate 与 MIDI 长度）。

---

## 6. 边界与风险

1. **1 MB 的“样本”**：`01 Intro` 有一次 start=0、end=1 MB。整段解码成 float 是 4 MB。C140 的先例是
   “整段解码、不设上限”（拖拽才拿得到完整样本），X1-010 要不要沿用，是本轮最需要决定的一件事。
2. **start/end 的粒度是 4 KB**：样本永远从 0x1000 的倍数开始；长度为 0 时核心立即 key off。
3. **`freq == 0`**：核心用 4 兜底（Meta Fox 的历史 hack）。我们照抄，否则除零。
4. **gate 改变**：从固定 80 ms 改成真实时长会改变 MIDI 的音符长度，是行为变更，需要单独说明与测试。
5. **ROM 体积**：每首歌 IR 里会多出最多 1 MB（`memory::rom` 的上限），属于既定做法（C140 2 MB）。
6. **行数**：16 行全部 `present`，与硬件一致；PCM 与波形行混排，行名仍按通道编号。

## 7. 验证计划

| 层 | 断言 |
|---|---|
| 波形模式 | 128 点表、`tableWave`、`sampleRate = clock×pitch/524288` |
| PCM 模式 | `wave` 长度 = `end−start`、首值 = `rom[start]/128`、`sampleRate = clock/8192×freq` |
| PCM 结束 | 真实时长到期后 gate 关闭（不再依赖 80 ms） |
| 行 | harness：`engine.wave.0 == 128`（波形）与 `== 样本长度`（PCM）|
| 导出（若做） | 13 首各出 N 个 `x1010_*`，首名与长度固定 |

## 8. 需要你确认

1. **PCM 行整段解码**（C140 先例，最坏 4 MB/次）还是**设上限**（如 65 536 点均匀抽样，拖拽会变短）？
2. **gate 改成真实时长**（推荐，MIDI 长度随之变化）还是保持 80 ms？
3. 这一版是否**同时做 PCM 导出收集器**，还是先只做可视化、导出另开一轮？
4. 波形与 PCM 共用 `state.wave` + `tableWave` 区分——沿用这个约定？
5. 包络 RAM 明确不做（只影响响度），可以吗？

## 9. 已实现（2026-11-12）

按方案 A + B 落地：

- 解码器补 `kRequirements{16 MHz, 0x91, 1 MB}` 与 `attachMemory`，保存 4 KB 波形 RAM，跟踪 `0x04/0x05`；
- PCM 行显示 `rom[start..end)`（`/128`），速率 `clock/8192 × max(freq,4)`，`tableWave=false`；
  波形行显示 128 步表（`/128`），速率 `clock×pitch/524288`，`tableWave=true`；
- gate 改为真实时长（`(end − start) / rate`），旧的“80 ms”断言相应改写；
- PCM 样本按 `(start, length)` 缓存并被 **262 144 点**护栏截断（仅供显示；导出仍由
  `settings.export.sampleSeconds` 控制文件长度）；
- 新收集器 `collectX1010Samples` 输出 `x1010_*` 8 位有符号 WAV，`02 Stage 1` 出 7 个文件；
- 波形 RAM 与包络 RAM 都通过 `0xC8` 的偏移写入，0x1000-0x1FFF 进表、0x80-0xFFF 忽略。

验证：`testX1010WaveAndPcm`（128 步表、PCM 字节、两种速率、真实 gate），`pcm-x1010.txt`
（7 个样本 + 首名），`engine.wave.2 == 128` / `wave.3 == 8192` 在 harness 上通过。
