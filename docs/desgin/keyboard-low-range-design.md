# 键盘视图：低于 C2 的音怎么办

- **状态**：评审中（Q1/Q3/Q4/Q5 已定；Q2 待澄清；键宽改为固定像素，见 §8）
- **日期**：2026-10-24
- **前提**：箭头已改为左右指向（`3b813ff`）；本稿只解决"音域窗口从哪开始"

## 1. 问题

键盘窗口的左边界固定 C2（MIDI 36）。**2A03 的三角声道常年在 C1–C3 走低音**，那部分音符没有键可亮，只有一个左箭头。

这在实际曲子里不是边缘情况：`Entry025.nsf` 的三角是 G3，但同类曲子（尤其低音线明显的）会到 C1。

窗口宽度换算成八度是有限的：

| 窗口宽 | 八度 | 固定从 C2 起 | 代价 |
|---|---|---|---|
| 900 | 3 | C2–B4 | C1、C5 以上看不到 |
| 1100 | 4 | C2–B5 | C1 看不到 |
| 1500 | 7 | C2–B8 | 基本够，但顶端是空的 |

## 2. 四种做法与取舍

| 方案 | 做法 | 优点 | 问题 |
|---|---|---|---|
| **A. 起始音设置** | 设置里选 C1 / C2 / C3 | 简单、可预测 | 全局一个值，无法同时对一首低音歌和一首高音歌都合适 |
| **B. 按歌自动适配** | 观察这首歌实际用到的音域，把窗口对齐到它 | 每首歌都贴合；无抖动 | 需要"只扩不缩"否则会来回跳；开头几秒还在观察 |
| **C. 实时跟音平移** | 音在窗外就把窗口挪过去 | 永远看得到当前音 | **否决**：13 行各自平移，横向比较立刻失效，且画面持续晃动 |
| **D. 每行独立音域** | 每个通道按自己用到的音域定窗口 | 每行都最紧凑 | **否决**：两行的 C3 会落在不同位置，"谁的音更高"看不出来 |

## 3. 建议：B + A + 手动平移

### 3.1 自动适配（只扩不缩）

```
观察：每个通道出现过的音（note 值）
取   ：minNote / maxNote
窗口：以八度为粒度，尽量覆盖 [minNote, maxNote]
     └ 若跨度过大（> 当前可见八度数），改为以中位数为中心
规则：只扩不缩；换歌时重置
```

为什么"只扩不缩"：一首歌里低音偶尔出现一次，若窗口随之上下移动，整页会不断跳动。**扩一次就停住**，比精确跟随更可读。

### 3.2 起始音设置（自动之外的兜底）

| 值 | 说明 |
|---|---|
| **自动**（默认） | 按 §3.1 |
| **C1 / C2 / C3** | 固定左边界，给喜欢稳定参照的人 |

选择固定值时不再自动适配——用户已经明确指定了参照。

### 3.3 手动平移

两个入口，都作用于**所有行**（保持同一参照）：

- **Ctrl + 滚轮**：每次一个八度；
- **点击左右箭头**：向箭头方向平移一个八度。

手动平移后，这首歌内不再自动适配（直到换歌）。

### 3.4 箭头继续存在

自动适配之后仍可能超出（音域跨度大于可见八度数）。此时箭头照旧，作用从"提示"升级为"按钮"——点它就能去看。

## 4. 界面变化

设置 → 键盘，新增一行：

```
起始音        [ 自动 ▾ ]        C1   C2   C3
[✓] 音符超出可见键位时显示箭头
```

无其它可见变化；键盘行布局不动。

## 5. 实现

| 步 | 内容 |
|---|---|
| 1 | `KeyboardPanel` 记录 `observedMin/observedMax`，在 `setSnapshot()` 里累积（只扩） |
| 2 | `baseNote` 由「设置值」或「observed 拟合」决定，八度对齐 |
| 3 | `paintKeyboard` 用 `baseNote` 取代常量 `firstNote = 36` |
| 4 | Ctrl+滚轮 / 点击箭头 → `baseNote` 平移一个八度，并置 `manual = true` |
| 5 | 设置页加「起始音」下拉；`songChanged()` 时重置观察与手动标记 |

约 120 行，仍在 `ContentSlot.cpp` 与设置页内。

## 6. 风险

| 风险 | 处理 |
|---|---|
| 开头几秒窗口会变一次 | 只扩不缩，最多变一次；且首次适配延后 0.5 秒再定 |
| 手动平移后忘了回自动 | 换歌即恢复；设置里改回"自动"也恢复 |
| 八度对齐导致覆盖不足 | 对齐到 C，宁可多显示一个八度也不把 C 键错位 |

## 8. 固定像素键宽（新增评审项）

提议：**键宽固定，窗口越宽显示越多键**。结论是合理，而且比现在更好。

### 8.1 现在的做法是"拉伸"

```cpp
octaves    = jlimit (3, 7, keysWidth / 140);   // 20 px 作为下限
whiteWidth = keysWidth / (octaves * 7);        // 再拉伸填满
```

结果：1500 px 时是 7 个八度、白键 26 px；2000 px 时**还是 7 个八度**，只是键更胖。宽度增加得到的是"更大的键"，不是"更多的键"——与直觉相反。

### 8.2 改为固定 20 px

```
白键数  = keysWidth / 20            // 装得下几个
白键宽  = 20 px（恒定，不拉伸）
音域    = 从基准音起，装到装不下为止（右侧允许是"半个八度"）
```

| 窗口宽 | 键列宽 | 白键数 | 大致音域（基准 C2） |
|---|---|---|---|
| 900 | 450 | 22 | C2 – D5 附近 |
| 1100 | 650 | 32 | C2 – A6 附近 |
| 1500 | 1050 | 52 | C2 – G8 附近 |
| 2000 | 1450 | 72 | 已到上限，右侧留白 |

### 8.3 三条约束（否则会出问题）

| 约束 | 原因 |
|---|---|
| **上限 B8（MIDI 127）** | 再往右没有音可点；剩余空间留白，不拉伸 |
| **下限 2 个八度** | 键列窄于 280 px 时，键宽允许缩到 16 px，而不是硬留 2 个八度把键挤没 |
| **基准音左对齐** | 不足一个白键的余量留在右侧，不参与分配 |

副作用只有一个：很宽的窗口右边会出现"半个八度"。C 的标签仍在整八度处，不影响读。

## 9. Q2 在问什么

两种"知道这首歌用了哪些音"的方式：

| | **只扩不缩**（建议） | 前 2 秒取样 |
|---|---|---|
| 做法 | 播放全程一直记录出现过的音；窗口只向外扩，从不缩回 | 只听前 2 秒，之后锁定 |
| 歌到 3 分钟时出现更低的音 | 窗口**扩一次**（整页跳一格，之后不动） | 不扩，只有左箭头提示 |
| 好处 | 后半段的低音也能看到 | 画面绝对稳定 |
| 代价 | 播放中可能跳一次 | 后半段低音永远看不到 |

建议 **只扩不缩**：跳一次是可见的、可理解的；永远看不到是无声的缺陷。
