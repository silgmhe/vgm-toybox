# 键盘视图：八度标记与自适应音域

- **状态**：设计稿，待评审
- **日期**：2026-10-24
- **涉及**：`plugin/Source/ui/ContentSlot.cpp` → `ContentSlot::KeyboardPanel::paintKeyboard()`

## 1. 两件事

| 需求 | 目标 |
|---|---|
| **八度标记** | C2、C3、C4… 以文字画在键盘上，让人一眼知道当前高亮的是哪个八度 |
| **随宽度伸缩** | 窗口越宽，键盘显示的八度越多；变窄则减少，而不是把键压到不可读 |

## 2. 现在的问题

`paintKeyboard()` 里的音域是写死的：

```cpp
constexpr int firstNote = 36;		// C2
constexpr int octaves = 4;			// C2–B5
const float whiteWidth = (float) area.getWidth () / (float) (octaves * 7);
```

宽度全部由**键宽**吸收：窗口拉到 1600 px 时白键约 40 px（过于空旷），收到 900 px 时约 12 px（读不出音名）。

## 3. 自适应规则

### 3.1 可用宽度

键盘列的宽度是窗口宽度减掉固定的四列与间距：

```
固定列 = 名称 72 + 间距 6 + M 26 + 4 + S 26 + 10 + 音高 56 + 6 + 波形 88 + 10 + 电平 96 + 10 = 410
键盘列 = 内容区宽度 − 2×20(内边距) − 410 ≈ 窗口宽度 − 450
```

### 3.2 八度数量

以**白键最小宽度 16 px** 为界，向下取整；上限 7 个八度，下限 3 个：

```cpp
int octaves = juce::jlimit (3, 7, (int) (keysWidth / (7 * 16)));
```

| 窗口宽度 | 键盘列 | 八度 | 白键宽 | 音域 |
|---|---|---|---|---|
| 900 | 450 | **3** | 21.4 | C2–B4 |
| 1100 | 650 | **4** | 23.2 | C2–B5（现状） |
| 1280 | 830 | **5** | 23.7 | C2–B6 |
| 1500 | 1050 | **7** | 21.4 | C2–B8 |
| 1800 | 1350 | 7（封顶） | 27.6 | C2–B8，键更宽 |

超过 7 个八度不再增加，多余宽度留给键宽（上限 28 px，再宽也只是更好点按）。

### 3.3 左边界固定

**左边界恒为 C2（MIDI 36）**，宽度增加时向**右**扩展。

理由：拖窗口时键位不应左右乱跳。若以 C4 居中向两侧扩展，每变一次宽度所有键都会平移，高亮的那一个会"滑来滑去"，看起来像 bug。

## 4. 八度标记

### 4.1 位置与样式

```
┌─ 白键 ─┬─ 白键 ─┬─ 白键 ─┐
│        │        │        │
│   ▁▂▃  │        │        │
│  C2    │  D2    │  E2    │   ← 只标 C 键
└────────┴────────┴────────┘
```

- **只标 C 键**，文字在键的底边、水平居中、距底 2 px；
- 字号 8.5 px，颜色 `theme::secondaryText()`；
- 高亮键（正在发声的那个）文字用 `theme::onAccent()`，其余 C 键用次要色。

### 4.2 防拥挤

| 白键宽 | 行为 |
|---|---|
| ≥ 15 px | 每个 C 都标 |
| 10–15 px | 隔一个八度标（C2、C4、C6） |
| < 10 px | 不标（此时键本身已经读不出来） |

### 4.3 与"当前音名"的关系

行内已经有一条规则：**正在发声的键上写音名**（如 `G5`）。当发声音本身就是 C 时，两个标签会重叠 —— 此时只画一个，优先用行内音名（字号稍大），八度标记跳过该键。

## 5. 超出音域时

3 个八度（C2–B4）时，一首在 C6 上演奏的曲子会没有键可亮。

**处理**：在键盘左/右端点画一个小箭头（`◀`/`▶`，8 px），并在箭头旁写该音的八度数字（如 `6`），表示"音在上面，超出显示范围"。

不做自动平移：那会让整条键盘随音符左右滑动，13 行各自滑动，视觉上无法比较。

## 6. 实现

| 步 | 内容 |
|---|---|
| 1 | 抽出 `octavesFor (int keysWidth)`，替换写死的 `octaves = 4` |
| 2 | `paintKeyboard` 按新音域绘制；左边界仍取 C2 |
| 3 | C 键底部画八度标记，含 4.2 的三档密度 |
| 4 | 发声键是 C 时跳过重复标记（4.3） |
| 5 | 音高超出音域时画端点箭头（§5） |

改动集中在 `paintKeyboard()` 一个函数，约 60 行；`buildRows()` 与数据结构不动。

## 7. 风险

| 风险 | 说明 | 处理 |
|---|---|---|
| 重绘开销 | 7 八度 × 13 行 ≈ 1100 个键，30 Hz | 实测；若超预算，把静态键位缓存成 `Path` |
| 拖窗抖动 | 跨过 16 px 阈值时八度会跳变 | 用 16 px 阈值 + 只在 `resized()` 时重算，拖窗过程中不反复切换 |
| 文字重叠 | 窄键时 `C2` 与邻键重叠 | 由 4.2 的密度档位控制 |

| **Q1** | 左边界固定 C2 向右扩展，还是以 C4 为中心向两侧扩展？ | **固定 C2**，拖窗时键位不跳 |
| **Q2** | 八度上限 7（C2–B8）够不够？ | 够；再高已是音阶极限 |
| **Q3** | 白键最小宽度取 16 px？ | 是；低于它音名读不出 |
| **Q4** | 超出音域用端点箭头，还是自动平移键盘？ | **箭头**，平移会让 13 行各自滑动 |
| **Q5** | 八度标记只标 C，还是 C 与 F 都标？ | **只标 C**，F 会让密度翻倍 |
