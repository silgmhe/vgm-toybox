# YM2612 DAC 的可视化与 PCM 导出设计

**入口**：键盘页 YM2612 的第 7 行（DAC）；File → Export → PCM Samples；行拖拽
**相关**：`docs/memo/2026-11-10-the-dac-is-a-latch.md`、`docs/research/2026-11-10-vgm2fur-dac-runs.md`、
`docs/research/2026-11-10-dac-row-as-a-sample.md`、`docs/research/2026-11-10-dac-load-cost.md`、
`docs/research/2026-11-10-dac-wav-and-daw-resampling.md`、本文档 §9.20

---

## 1. 需求（用户的原话，决定了整个设计）

1. “DAC 行现在像在流，别的采样行是‘触发的那一个样本’，希望一致。”
2. “一个鼓一个文件，和 vgm2fur 转出来的 `.fur` 里那些采样一致。”
3. “不同采样用不同音符，从中央 C 按半音上移，方便扒带分辨底鼓和军鼓。”
4. “导出的 PCM 拖进 32 位 DAW 后高频变闷，Furnace 里不会。”

这四条约束对应四件事：**击打的边界**、**导出的单位与速率**、**音名**、**文件的时间轴**。

---

## 2. 这颗芯片为什么特殊

别的采样芯片用寄存器指向一段 ROM；YM2612 的第六通道是一个 **8 位锁存器**：

```
Z80 ──字节──► [0x2A] ──► DAC 输出（保持到下一次写）
        ▲
        │
  写得多快 = 音高     写什么 = 波形     写多久 = 时长
```

没有地址、长度、循环位或速率寄存器。VGM 只记录四件事：

| 命令 | 含义 |
|---|---|
| `0x80-0x8F` | 取 PCM 银行的下一个字节写进 `0x2A`，再等 n 个采样 |
| `0x52 0x2A xx` | 直接写一个字节（停止、调电平，**不是**样本字节） |
| `0xE0 offset` | 把银行读指针挪到 offset——驱动“从表里第 N 项开始播” |
| `0x2B bit7` | 打开 DAC |

**银行没有地址，`0xE0` 的去重偏移是驱动的采样表**——但它是**寻址**表，不是**边界**表（见 §3）。

---

## 3. 一个“击打”的定义（整个设计的核心）

一条 run = 驱动**实际播放**的一串字节，边界由两件事决定：

1. `0xE0`（正在播 / 还没播过）→ 新的一击；只在静音里挪指针不算，并丢掉那些静音字节；
2. 两个字节之间停顿 **≥512 采样（11.6 ms）** → 切开，新一击从 `start + length` 继续。

`0xE0` **不是样本边界**，实测：

| 曲子 | 表项（相邻偏移） | 实际击打 |
|---|---|---|
| Marble `0x0A80` | 382 B | **1 693 B**（跨过 `0x0BFE`、`0x1124`） |
| Labyrinth `0x0000` | 到 `0x0770` | **3 808 B**（跨过 `0x0770`） |
| Green Hill `0x0060` | 5 302 B | 1 488 B（只播了开头） |

按表项切会**在驱动从不切割的地方切开**，或者**画出从未播放的字节**；按击打切则与
`vgm2fur/chips/sampler.py` 一致（本项目的导出目标就是它写进 `.fur` 的那一份样本集）。

速率：`tickRate × length ÷ duration`，**整数除法**；`duration` 计入 ≤11.6 ms 的小停顿，不记切开那次长停顿。
`(start, length)` 相同的击打归为同一个样本，**首次速率胜出**。

## 4. 分层

```
SongIr { writes(0x2A + fromStream), dacSeeks }
   │
   ├─ dac::buildTable()  ← 一次，在 LibvgmSongInstance::prepare()
   │      ├─ bankFor(): 0x67 的 0x00/0x80 块按流序拼接
   │      ├─ runsFor(): 两个有序流（0x8n 写 / 0xE0 seek）双指针合并 → Sampler → Run[]
   │      └─ assignSampleIndices(): (start,length) 首次出现编号 → Run::sample
   │
   ├─ 行：LibvgmTrackPlayer::applyDacHit()  ← dac::hitAt(runs, 当前 tick)
   │      覆盖 wave / sampleRate / note
   │
   └─ 导出：collectYm2612DacSamples(ir, table)  ← Run → DecodedSample → WAV
```

**解码器不参与**：`OpnDecoder` 仍然只回答“锁存器收到了什么”（最近 4096 字节的窗口、滑动均值、50 ms 触发脉冲），
它看不到 `0xE0`，也不该知道驱动把指针挪到哪。击打是驱动层面的事实，属于播放层与导出层。

---

## 5. 表的构建：一次，一趟

`LibvgmSongInstance::prepare()` 建一次 `dac::Table`（`tickRate` + `device` + `bank` + `runs`），
通过 `setReplaySource()` 以 `shared_ptr` 交给每个 track player，并传给导出。

**为什么强调“一次”**：`02 Green Hill Zone` 有 459 546 条 `0x8n` 写；按 track player 各建一次（12 个）时，
加载为此多花约 200 ms，而其中 11 张表从未被读取（只有 `trackPlayers[0]` 会被 `captureState` 问到）。

**为什么没有排序**：`ir.writes` 与 `ir.dacSeeks` 本来都按时间有序，合并即可；同刻次序固定为
seek 先于字节，再按 `streamOrder`——这与旧实现 `stable_sort` 的结果一致，导出的名字因此不变。

实测：单次建表 **1.81 ms**（原 12 × 16 ms ≈ 197 ms）；GHZ 进程总时长 633–773 ms → 353–383 ms。

---

## 6. 行画什么

`applyDacHit()`：

1. `dac::hitAt(runs, samples)` —— 取“此刻在播的那一击，否则最后一击”。**刻意“或之前”**：其他采样行播完也保持
   最后那个样本，DAC 行不该变空白；
2. 波形：懒解码 `bank[start..]`，按 `(start,length)` 缓存（`shared_ptr`，切歌时随播放器清空）；
   超过 **8 192 点**时**全段均匀抽样**（不是只画开头——长击打要看包络）；
3. `sampleRate`：该击的 `tickRate × length ÷ duration`，与导出文件头同一个数；
4. `note`：见 §8。

**拖拽同源**：行的 `waveValues()` 就是击打的字节，所以拖出来的 WAV 与批量导出的是同一份——以前拖的是
“最近 4096 字节 @ 滑动均值”，那是另一份东西。

## 7. 导出

- 单位：一次击打，一个文件；
- 名字：`ym2612dac_<序号>_<起始偏移>_<长度>`，序号即 `Run::sample`（§8 的音名同源）；
- 数据：`pcm8Signed`——DAC 的静音是 `0x80`，转成有符号后与 `.fur` 的 `SMP2` 逐字节相同；
- 速率：整数除法，与 `.fur` 的 compat/C-4 rate 相同；
- 上限：收集器 30 s 硬顶，写出层再叠设置里的“单个采样最长 N 秒”；
- 不滤短击打：Green Hill 的 93/96 字节停止音照导（参考实现也照导）。

`02 Green Hill Zone` 得到 8 个文件，名字/长度/速率与 `.fur` 的 8 个 `SMP2` 一一对应：

```
00 000000 5398 @14783   01 000000 1584 @7978   02 001516 3810 @23105   03 0023F8 3808 @23128
04 0032D8  116 @8018    05 000000   96 @8301   06 000060 1488 @7981    07 000000   93 @8285
```

## 8. 音名：C4 + 样本序号，取余循环

一行装下所有鼓，固定 C4 分不出底鼓与军鼓。规则只有一份（`dac::noteForSample`）：

```
note = 60 + (sample % 60)      // C4 起，五个八度 C4..B9，第 60 个回到 C4
```

- **行**：`applyDacHit()` 覆盖 `state.note` / `state.frequency`；
- **MIDI**：`MidiSequenceBuilder::flushOpn()` 对 YM2612 的 DAC 通道，用**同一张表**、同一个函数按击打改写音名；
- **文件名**：同一个序号，所以 `ym2612dac_07_…` ↔ G4 ↔ MIDI 的 G4。

同一记鼓重复播放时序号不变、音名不变——这正是“再听一次认出那记军鼓”所需要的行为。

---

## 9. 文件的时间轴：为什么按宿主速率写

导出时把电平**按目标速率零阶保持**（`WaveExport.cpp` 的 `heldAt`，与波表 `nearest()` 同一条规则）：

```
n = round(len × target / rate)
out[i] = in[(i × len) / n]        // 整数除法 = 零阶保持
```

原因不是位深（8 位→float32 是精确的），而是**重采样**：文件按芯片速率（8–23 kHz）写，44.1/48 kHz 的工程导入时
会带限到文件自己的 Nyquist，而 8 位 DAC 的“颗粒感”正是零阶保持的镜像（`rate × k ± f`）——它们恰好在带外。
把保持烘进目标速率的文件里，工程就能 1:1 播放。

设置 `export.sampleRate`：`0` 跟随宿主（默认）、`-1` 芯片速率、`44100/48000/96000` 固定；插件取
`processor.getSampleRate()`，独立版取 `PlaybackEngine::outputSampleRate()`，未知时 44 100。

实测（Green Hill 三段）：线性转换削掉 `rate/4` 以上 6–20 dB，保持版留下 50–87% 的平台。

## 10. ADR

### ADR-001：单位是“击打”，不是“区域”

`0xE0` 是寻址表，驱动会跨过它连续播；按区域切会切开或补上从未播放的字节，也与导出目标（`.fur`）不一致（§3）。

### ADR-002：击打表建在播放层，不在解码器

解码器看不到 `0xE0`；把 `seek()` 塞进 `IChipDecoder` 会让每个解码器都多一个空方法，还要把同一套 Sampler 复制一份。
现在“解码器描述锁存器，播放层描述驱动”的分工与既有分层一致。

### ADR-003：一张表、一次、共享

按 track player 各建一次多花约 200 ms 且 11 张表无人读取（§5）。表随 `SongIr` 生命周期，
`shared_ptr` 交给播放器与导出，切歌时释放并清波形缓存。

### ADR-004：合并而不是排序

两个输入本来有序；`stable_sort` 46 万条事件是 16 ms 与 7 MB 临时内存的来源，合并是一趟 O(n)（§5）。

### ADR-005：速率用整数除法，与参考实现对齐

`44100 × length // duration` 是 `vgm2fur` 的算法；用浮点再四舍五入会在边界上差 1，导出文件与 `.fur` 就对不上了。

### ADR-006：音名用 C4 + 序号并取余

用户的目的是“认鼓”，序号是唯一稳定的身份（同一段字节），音高本身没有意义；取余保证超过 60 个样本时仍在
MIDI 音域内，代价是第 60 个之后重复音名（少见）。

### ADR-007：容器写 `pcm8Signed`，不写无符号

DAC 的静音是 `0x80`；有符号后 WAV 载荷与 `.fur` 的样本数据逐字节相同，读者不必在导入时再减半幅。

### ADR-008：拖拽与批量走同一规则

两条路径读同一份 `waveValues()` 与同一个表；否则同一个字节在两种用法下听感不同——这正是修复前的问题。

## 12. 已知限制

1. **双 YM2612**：`0xE0` 在 VGM 里不指芯片，loader 也只创建一颗（`0x53` 是 port 1），表按“第一颗”建；
   若将来出现第二颗带流字节的芯片，需要它自己的 seek（格式目前没有）。
2. **没有 seek 的驱动**：表退化为按 11.6 ms 停顿切，行为与旧窗口接近，不会更差。
3. **静音入口与重复素材**照导：Green Hill 的 `0x0000` 有 93/96 字节停止音；`0x0636` 与 `0x23F8` 是同一段
   3 808 字节的拷贝，按位置去重所以两份都在。
4. **MIDI 的音名映射**只有共享函数与编译期保证，端到端（导出 MIDI 进 DAW）还没有自动化用例。
5. **导出的时间轴**只对“工程速率 = 目标速率”完全无损；固定值导出到别的工程仍会被重采样一次。
