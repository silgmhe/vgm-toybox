# 视图切换设计：Mixer / Chip State / Oscilloscope

- **状态**：已实现（评审通过：Q1 都显示、Q2 都显示、Q3 占位文案、Q4 不保留独立页）
- **日期**：2026-10-24
- **背景**：Tab 方案已回退（`5078b5f`、`718a850`）。改为「视图菜单切换内容区」，而不是「页面级 Tab」。

## 1. 现状与问题

当前有两个**页面级**视图，由顶部「视图」菜单切换：

```
[顶部条]  打开文件…                   状态
┌────────────────────────────────────────┐
│ 曲目信息卡片                            │
│ 芯片静音卡片（2A03 / N163）             │   ← ViewStack 页面 A（播放）
│ 混音器                                  │
└────────────────────────────────────────┘
┌────────────────────────────────────────┐
│ 走带控制器                              │
└────────────────────────────────────────┘
```

问题：

1. 切到「可视化」页时，**整个页面**被替换，走带控制器也跟着消失——而它是随时要操作的；
2. 视图菜单表达的是「换一页」，但用户真正想说的是「**换上面那块内容**」；
3. Tab 方案把混音器和曲目信息挤掉了，代价过大，已回退。

## 2. 提案

### 2.1 一个页面，内容区可换

```
[顶部条]  打开文件…                   状态
┌────────────────────────────────────────┐
│ 曲目信息卡片              ← 固定（见 Q1）│
│ 芯片静音卡片              ← 固定（见 Q2）│
├────────────────────────────────────────┤
│                                          │
│        内容区（三选一）                   │
│        Mixer / Chip State / Oscilloscope │
│                                          │
└────────────────────────────────────────┘
┌────────────────────────────────────────┐
│ 走带控制器                ← 永远可见、可操作 │
└────────────────────────────────────────┘
```

- **固定**：顶部条、曲目信息卡、芯片静音卡、走带控制器；
- **可换**：中间那块矩形（现在放混音器）。

### 2.2 视图菜单

```
视图
 ├ ✓ Mixer          Ctrl+1
 │   Chip State     Ctrl+2
 │   Oscilloscope   Ctrl+3
```

- 勾选当前项；
- 默认 **Mixer**，即现在的布局；
- 三项互斥，切换只重排内容区，不动其它区域。

### 2.3 三个内容区

| 视图 | 内容 | 现状 |
|---|---|---|
| **Mixer** | 现有的混音器（逐轨推子、静音/独奏、主控） | 已有，原样搬入 |
| **Chip State** | 芯片面板：每通道名称、音高（键盘高亮）、音量条、波表；右上「导出波表」 | 已有（`VisualiserView` 的内容），**去掉它的卡片外壳**，由内容区统一提供圆角背景 |
| **Oscilloscope** | 占位文案 | 新增，一句话 |

### 2.4 尺寸与自适应

- 内容区有 `minHeight`（暂定 180）：窗口太矮时优先压缩曲目信息卡与芯片卡，最后才压缩内容区；
- 走带控制器固定高度，始终完整显示（`TransportPanel::preferredHeight`）；
- 内容区宽度撑满，高度 = 页面高 − 顶部块 − 走带 − 间隙。

### 2.5 状态与持久化

| 项 | 决定 |
|---|---|
| 默认视图 | Mixer |
| 换歌 | **保持**当前视图（不重置） |
| 重启后 | 记住上次选择，键 `ui.view`（`mixer` / `chip` / `scope`） |
| 无歌曲时 | 三个视图都可切换；Chip State 显示「该格式暂未提供逐通道状态」，Mixer 显示空轨道 |

### 2.6 实现草图

```
ui/PlayView.h/.cpp                 ← 唯一的 View
    SongInfoPanel   (固定)
    ChipPanel       (固定，芯片静音勾选)
    TransportPanel  (固定)
    ContentSlot     ← 新增：持有三者之一，负责切换与布局

ui/ContentSlot.h/.cpp              ← 新增
    enum class ContentView { mixer, chipState, oscilloscope }
    setView (ContentView)
    ContentView getView () const
    juce::Component& 当前内容

    MixerPanel      （已有，搬入）
    ChipStatePanel  ← 由 VisualiserView 的内容改造：去掉卡片外壳与 Tab，保留面板与导出按钮
    ScopePanel      ← 新增占位
```

- **ViewStack 只剩一个页面**（`PlayView`），`VisualiserView` 删除；
- 「视图」菜单不再来自 ViewStack，而由 `PlayView` 暴露的三项构造（`ViewStack` 的页面列表机制保留给将来可能的多页面）；
- 快捷键 `Ctrl+1/2/3` 由编辑器转发到 `PlayView::setContentView()`。

### 2.7 搬迁步骤（评审通过后执行）

1. 新增 `ContentSlot`，把 `MixerPanel` 原样移入，`PlayView` 的布局改为「固定块 + 内容区 + 走带」；
2. `VisualiserView` 的绘制代码改成 `ChipStatePanel`（去掉 Tab 与卡片外壳），接入 `ContentSlot`；
3. `ScopePanel` 占位；
4. 视图菜单改为三项 + 快捷键 + 持久化；删除 `VisualiserView` 与它的页面注册；
5. 构建、`ctest`、出包、手测三视图切换。

## 3. 验收清单

- [ ] 默认打开是 Mixer，布局与现在一致；
- [ ] 视图菜单三项，勾选当前项，`Ctrl+1/2/3` 同样生效；
- [ ] 切到 Chip State：曲目信息与芯片卡**留在原位**，只有中间区域变化；走带仍可见可操作；
- [ ] 切到 Oscilloscope：同上，中间是占位文案；
- [ ] 切回 Mixer：混音器状态（推子、静音）**不丢失**（组件常驻，仅切换可见性）；
- [ ] 播放中来回切换不产生爆音、不中断（切换只影响可见性与布局）；
- [ ] 重启应用后停在最后选择的视图；
- [ ] 窗口很矮时走带仍完整显示，内容区按 §2.4 压缩。

## 4. 待评审的四个问题

| # | 问题 | 我的建议 |
|---|---|---|
| **Q1** | 曲目信息卡（标题/艺术家/版权）在三个视图里都常驻，还是只在 Mixer 里显示？ | **常驻**：它是「这首歌是什么」的上下文，与看混音器还是看芯片无关 |
| **Q2** | 芯片静音卡（2A03/N163 勾选）常驻吗？ | **常驻**：Chip State 只读，静音操作仍需要一个地方；且它很小 |
| **Q3** | Oscilloscope 占位文案写什么？ | 「示波器尚未实现」——一句话，不画假曲线 |
| **Q4** | 切换视图时，是否保留「可视化」这个独立页面做过渡？ | **不保留**：两套入口会让人分不清哪个才是「看芯片」的地方 |

## 5. 与已回退的 Tab 方案的区别

| | Tab 方案（已回退） | 本方案 |
|---|---|---|
| 位置 | 页面内 Tab 控件 | 视图菜单 + 内容区替换 |
| 混音器 | 被替换掉 | **是默认视图**，不丢 |
| 曲目信息 | 被替换掉 | 保留 |
| 走带 | 保留 | 保留 |
| 菜单 | 变成只有一个「播放」页 | 三项内容视图，语义明确 |
