# 键盘视图设计（Keyboard）

- **状态**：设计稿，待评审
- **日期**：2026-10-24
- **对应视图**：视图菜单 → 键盘（`ContentView::keyboard`，`ContentSlot::KeyboardPanel`）
- **参照**：MDPlayer 的芯片窗口；用户提供的线框图

## 1. 线框图与本文的关系

用户提供的结构：

```
┌ 2A03 ─────────────────────────────────────────────────────────────┐
│ Pulse 1 │M/S│音高│波表│  钢琴键盘（高亮键带音名）  │音量 Meter│        │
│ Pulse 2 │M/S│音高│波表│  钢琴键盘                  │音量 Meter│        │
│ Triangle│M/S│音高│波表│  钢琴键盘                  │音量 Meter│        │
│ Noise   │M/S│音高│波表│  钢琴键盘                  │音量 Meter│        │
│ DMC     │M/S│音高│波表│  钢琴键盘                  │音量 Meter│        │
└───────────────────────────────────────────────────────────────────┘
┌ N163 ─────────────────────────────────────────────────────────────┐
│ Wave 1 … Wave 8   同上                                             │
└───────────────────────────────────────────────────────────────────┘
```

**总体判断：合理，可以照做。** 分组表头 + 每通道一行 + 五列，是这类视图里最省地方也最易读的形式。有四处需要调整，理由在第 3 节。

|---|---|---|

这是个好消息：**线框图里的两栏（2A03 + N163）今天就能填满**，不需要改 vendored 核心。

## 3. 需要调整的四处

### 3.1 每行一条键盘 → 键宽会很窄

按 13 行、每行一条 5 八度键盘算：内容区宽约 1100 px，去掉其它四列约 300 px，键盘得 800 px；5 个八度 = 35 个白键 → **每键 22 px**，勉强。若窗口窄一点就不可读了。

**建议**：每行键盘用 **4 个八度（C2–B5）**，28 个白键 → 每键 ≈ 28 px。需要更高/更低的音（极少）时，该键画在边缘并用箭头标出。

### 3.2 2A03 没有"波表"

方波由硬件按占空比生成，三角是固定 32 级阶梯，噪声是 LFSR，DMC 是 1-bit delta——**都不在内存里**。

**建议**：这一列改叫「波形」，按芯片类型**合成一个周期来画**：

| 通道 | 画什么 |
|---|---|
| Pulse 1/2 | 按 `duty`（12.5 / 25 / 50 / 75%）画方波 |
| Triangle | 32 级阶梯 |
| Noise | LFSR 的一个短周期（短模式 93 步、长模式 32767 步取一段） |
| DMC | 1-bit 阶梯（+1/-1 累加后归一化） |
| N163 / FDS | 真实波表（已有） |

这样这一列对所有通道都有内容，且**画的是真的**（由寄存器推出来的），不是占位图。

### 3.3 M/S 不能有第二份真相

混音器视图里已有每轨的 M/S。如果键盘视图维护自己的静音状态，两个视图会不一致。

**建议**：键盘的 M/S **直接读写引擎的轨道静音/独奏**（`engine.setTrackMute/Solo`），与混音器共享同一份状态。

前提是通道能对应到轨道：`ChannelState` 增加 `int trackIndex`，由后端填（NSF 后端本来就是一条轨一个通道）。

### 3.4 13 行放不下

两组合计 13 行。按行高 40 px + 组头 26 px 算，约 **580 px**；加上外边距超过内容区高度（窗口 700 px 时内容区约 420 px）。

**建议**：`KeyboardPanel` 放进 `juce::Viewport`，纵向滚动；行高 40 px 不变。滚动条只在需要时出现。

## 4. 布局规格

| 列 | 宽度 | 内容 |
|---|---|---|
| 通道名 | 72 | `Pulse 1`、`Wave 3`（左对齐，静音时变灰） |
| M / S | 2 × 26 | 两个小方钮，激活时高亮（M 用警示色、S 用强调色） |
| 音高 | 56 | `C3`、`A#5`、`-`（无音高时） |
| 波形 | 88 | 一个周期的缩略图，阶跃绘制 |
| 键盘 | 剩余 | 见 §5 |
| 音量 | 96 | 水平条 + 峰值保持 |

- 行高 **40 px**，行间距 2 px；
- 组头 **26 px**：芯片名 + 通道数，例如 `2A03 · 5 channels`；
- 组之间空 10 px。

## 5. 键盘规格

| 项 | 值 |
|---|---|
| 音域 | **C2–B5**（4 个八度，MIDI 36–83） |
| 白键宽 | 可用宽度 ÷ 28，约 26–30 px |
| 黑键 | 白键宽的 62%，高度 60% |
| 高亮 | 该通道当前音高的键填 accent 色；黑键用更深一档 |
| 音名 | 高亮键上写 `C3` 这类名字；键宽 < 14 px 时省略 |
| 八度标记 | 每个 C 键下方写 `C2 C3 C4 C5`（小号字，次要色） |
| 无音高 | 整条键盘灰显，不画高亮 |

行内键盘共用同一套绘制函数，只是传入该通道的 note。

## 6. 音量 Meter 规格

- 水平条，长度 = `volume`（已归一化到 0..1）；
- 条内分三段配色：< 70% 用 accent，70–90% 用琥珀色，> 90% 用红色（对应"接近满幅"）；
- **峰值保持**：最近 1 秒的最大值画一条细线，缓慢回落；
- 静音或未激活时整条为底槽色。

## 7. 数据模型变更

```cpp
struct ChannelState
{
    std::string name;          // "Pulse 1" / "Wave 3"
    std::string chipName;      // "2A03" / "N163"

    bool active = false;
    int note = -1;
    float frequency = 0.0f;
    float volume = 0.0f;

    std::vector<float> wave;   // 已有：N163/FDS 的真实波表

    int trackIndex = -1;       // 新增：对应 engine.getTracks() 的下标，供 M/S 使用
    int waveKind = 0;          // 新增：0 无 / 1 真实波表 / 2 方波 / 3 三角 / 4 噪声 / 5 DMC
    float duty = 0.5f;         // 新增：方波占空比，waveKind == 2 时有效
};
```

分组不用新字段：UI 按 `chipName` 归组，保持通道原有顺序（2A03 在前）。

## 8. 实施步骤

| 步 | 内容 | 预估 |
|---|---|---|
| 1 | `captureState` 接 2A03（APU 4 通道 + DMC），填 `trackIndex/waveKind/duty` | 小，约 60 行 |
| 2 | `KeyboardPanel` 改为「分组 + 滚动 + 五列」骨架，先只画通道名和音高 | 中 |
| 3 | 键盘绘制（§5），含音名与八度标记 | 中 |
| 4 | 波形列（§3.2 的合成）、音量 meter（含峰值保持） | 中 |
| 5 | M/S 接到 `engine.setTrackMute/Solo`，并在 `refresh()` 里回读，保证与混音器一致 | 小 |

## 9. 风险

| 风险 | 说明 | 处理 |
|---|---|---|
| 重绘成本 | 13 行 × 27 键 × 30 Hz | 只重绘变化的行；键盘静态部分可缓存为 `Path` |
| M/S 回读 | 混音器改动后键盘视图需同步 | 每帧从 `engine.getTracks()` 读，不做本地缓存 |
| 2A03 `output` 量纲 | `TrackInfoBasic::output` 是原始输出，不是 0..1 | 按通道类型除以各自最大值得归一化，并在注释里写明来源 |
| 无 N163 的曲子 | 只有 2A03 一组 | 正常，单组也照此渲染 |
