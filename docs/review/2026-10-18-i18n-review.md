## 1. 总体结论

这次实现的核心方向是稳的：

- 语言包是不可变快照，`LanguageManager` 只交换 `shared_ptr<const LanguagePack>`，没有安装进程级 `LocalisedStrings`，避免了全局语言状态和窗口刷新竞争。
- 回退链明确：外部包 → 同标签内置包 → 英文包 → 键名；外部包可以只翻译部分键。
- 外部包边界清楚：不递归、只收 `*.lang`、跳过隐藏文件和模板、最多 128 个文件、单文件 1 MiB；单个文件失败只跳过自己。
- 设置同时保存稳定 ID 和语言标签：外部文件被删时可以退回同标签内置包，文件恢复后还能回到原选择。
- Language 页展示来源、标签、缺键数和跳过文件警告；不是“静默回退”。
- 文档质量高：`docs/desgin/i18n-design.md` 覆盖格式、回退、刷新协议、限制和明确不做的范围。

验证结果：

- 现有 `ctest` 11/11 通过，包括 `app.language`。
- `en.lang` 与 `zh-Hans.lang` 各 153 个键，无缺键、无多余键，占位符集合一致。
- 代码中静态出现的 `i18n::tr("...")` / `labelKey = "..."` 键都能在 `en.lang` 中找到。
- 抽查主要 `setText` / `setButtonText` / `setTooltip` 路径，未发现仍未走 `tr` 的界面文案。

## 3. 中等优先级

### M-1 解析器测试不足

**位置**

- `plugin/Source/i18n/LanguagePack.cpp:105-213`：手写解析器。
- `plugin/Source/i18n/LanguagePack.cpp:215-224`：`loadFromFile()` 不做文件大小检查。
- `plugin/Source/i18n/LanguageManager.cpp:103-169`：外部扫描、上限和逐文件跳过。
- `plugin/Tests/scripts/language.txt:1-46`：唯一的语言窗口测试。

**现象**

`language.txt` 覆盖了正常加载、选择、外部包回退和缺键数，但没有覆盖：重复键、未闭合引号、元数据缺失、空值/裸值、转义、BOM、解析失败文件隔离、128 个文件/1 MiB 上限、`rescan()` 在修复/删除文件后的行为，以及语言选择在重新构造 editor/重启后的持久化。

**影响**

语言包是用户可直接编辑的扩展点，边界回归可能表现为某个外部包静默不加载、错误行号不准，或启动时列表不完整。这类问题比 UI 文案更难复现。

**建议**

增加表驱动的小型单元测试，优先覆盖解析错误、文件隔离、上限和重扫；再补一个 `SettingsStore`/`LanguageManager` 的持久化测试。CJK 字体和布局单独做人工视觉检查（见 `L-5`）。

### M-2 英文参考包缺少键时没有护栏

**位置**

- `plugin/Source/i18n/LanguageManager.cpp:379-383`：缺键数只相对 `english` 计算。
- `plugin/Source/i18n/LanguageManager.cpp:394-427`：最终回退到键名。
- `plugin/Source/i18n/LanguageManager.cpp:103-169`：外部文件缺失 `id`/`language` 时只警告并跳过。

**现象**

英文包是参考包。如果新增代码键但漏加 `en.lang`，`countMissing()` 看不到；当前语言会显示原始键名，`zh-Hans` 的缺键检查也不会报警。当前 153/153 和静态引用检查都正常，所以这不是现存故障，而是下一次改文案的风险。

**影响**

漏键会在英文界面直接暴露为 `some.new.key`，而且现有测试不会失败。

**建议**

在 debug 构建中对“代码键不在英文包”加断言或日志；或在 CI 加一个静态/单元检查，保证 `en.lang` 覆盖所有代码键。同时保留 `language.txt` 对 `zh-Hans` 缺键数的断言。

### M-3 语言刷新仍靠手工协议，loop 工具提示漏刷

**位置**

- `plugin/Source/ui/TransportPanel.cpp:35-38`：`loopTooltip` 缓存文案。
- `plugin/Source/ui/TransportPanel.cpp:321-337`：`refreshLanguage()` 更新了循环按钮文字和 `loopBox` 工具提示，但没有更新 `loopButton`。
- `plugin/Source/ui/TransportPanel.cpp:690-694`：只有 `loops != lastLoopCount` 时才重设 `loopButton` 工具提示。
- `plugin/Tests/scripts/language.txt:1-46`：没有检查该工具提示。

**现象**

切换语言后，循环按钮的按钮文字会变，但工具提示保持旧语言；直到循环次数变化才刷新。这是当前实际可见的 bug。

**影响**

用户会看到中英混杂的提示；后续新增可翻译控件也可能漏加刷新步骤。设计文档已经列出刷新清单，但清单没有编译期约束。

**建议**

短期：在 `refreshLanguage()` 或 `refresh()` 中无条件重设 `loopButton` 的工具提示，并在 `language.txt` 增加断言。中期：至少加一个“切换语言后遍历代表性控件文本/工具提示”的测试；是否引入轻量监听器/统一刷新框架可另行评估，不必为此过度设计。

### M-4 Standalone 状态迁移没有测试，失败静默

**位置**

- `plugin/Source/Standalone/StandaloneApp.cpp:107-110`：迁移注释。
- `plugin/Source/Standalone/StandaloneApp.cpp:118-132`：旧状态文件路径。
- `plugin/Source/Standalone/StandaloneApp.cpp:153-187`：创建目录、移动/复制、失败处理。
- `plugin/Tests`：未找到 standalone-state 迁移测试。

**现象**

迁移只在目标文件不存在或为空时执行；`createDirectory`、`moveFileTo`、`copyFileTo` 的失败都没有日志或用户反馈。旧路径使用 `JucePlugin_Name`，未来产品显示名变化会改变“旧路径”。

**影响**

升级后音频设备、窗口状态可能丢失，且很难定位。这是同一提交附带的非 i18n 改动，但属于用户数据迁移风险。

**建议**

把路径计算和迁移逻辑抽成可注入目录的 helper，用临时目录测试移动、复制回退、目标非空、设置目录覆盖、移动失败等分支；旧应用名用历史常量而不是当前 `JucePlugin_Name`；失败至少写 `juce::Logger`。

### M-5 窗口测试依赖宿主语言和语言包顺序

**位置**

- `plugin/Tests/scripts/window-basics.txt:11`、`:52-54`：断言英文 `No file`、`Open Song` 等。
- `plugin/Tests/scripts/settings-pages.txt:29`、`:35`：断言英文 `Close Song`、`tray`。
- `plugin/Source/i18n/LanguageManager.cpp:210-223`：首次启动跟随系统语言。
- `plugin/Tests/scripts/language.txt:14-35`：用 0/1/2 位置选择内置/外部语言。

**现象**

`AppHarnessTest` 为每个脚本使用临时设置目录，但没有固定语言；没有 `language.txt` 的脚本会跟随宿主系统语言。中文 Windows 上这些英文断言会失败。CI 是英文环境所以没暴露。另外，新增内置语言会改变 `language.txt` 的索引。

**影响**

测试在中文开发机上不稳定，验证结果依赖环境；语言包顺序变化会让测试脆弱。

**建议**

让 harness 在临时设置目录下默认选择英文，除非脚本显式声明语言；或给脚本增加 `# language en`。`language.txt` 尽量按显示名/稳定 ID 选择，而不是位置索引。

## 4. 低优先级

### L-1 图标按钮的无障碍标题不随语言刷新

`plugin/Source/ui/MixerPanel.cpp:95-100` 和 `plugin/Source/ui/SyncGroup.cpp:190-195` 调用 `setName(tr(...))`；`plugin/Source/ui/IconButton.h:14-18` 注释说名称已翻译。但 JUCE 的 `ButtonAccessibilityHandler::getTitle()` 回退到 `Component::getTitle()`，再回退到 `Button::getButtonText()`；`setName` 不会改这两者。`IconButton` 构造时的按钮文本是英文，因此屏幕阅读器可能读到英文/旧标题。

建议在 `refreshLanguage()` 中调用 `setTitle(tr(...))`（或 `setButtonText`），并更新 `IconButton` 注释。视觉用户不受影响，所以定为低。

### L-2 语言页诊断硬编码英文

`LanguageManager.cpp:109,138,147` 的扫描警告、`LanguagePack.cpp` 的解析错误（如 `57,69,145,168,179,187,193,202,208`）都是英文，`SettingsOverlay.cpp:698-706` 原样展示。中文用户在 Language 页会看到英文诊断。

建议二选一：把错误类型做成结构化 code + 参数，由 UI 翻译；或明确文档化“诊断信息保持英文”并把文件路径/行号保留为技术细节。翻译时只翻译错误种类，不翻译路径。

### L-3 语言选择保存失败不在 Language 页显示，且同值选择不重试

`SettingsStore.cpp:141-164` 保存失败时设置 `lastErrorMessage`，但 `LanguageSettingsPage` 只显示 `LanguageManager` 的警告；`setLanguageSelection` 在值未变时提前返回（`:145-149`），保存失败后再次选择同一语言不会重试。用户可能以为已切换，重启后恢复旧语言。

建议 `selectById` 返回保存结果或在 `LanguageSettingsPage::refresh()` 显示 `store.lastError()`；当有错误时允许同值重试。可用只读设置目录做测试。

### L-4 语言包 API 的大小/格式契约不完整

`LanguagePack.h:30-31` 约定“大小由调用方检查”，`LanguagePack.cpp:215-224` 实际不查；目前只有 `LanguageManager` 做单文件 1 MiB、128 文件上限，理论上最多约 128 MiB 在首次 `tr` 时同步解析。直接调用 `loadFromFile` 的代码没有保护。

另外 `LanguagePack.cpp:158-161` 接受 `format:` / `countries:` 但不校验；未来 `format: 2` 文件会被当作 v1 静默读取。

建议把大小检查放进 `loadFromFile`，并考虑聚合上限；在格式未稳定前明确 `format` 为保留字段，或校验已知版本并拒绝未知版本。

### L-5 中文界面缺视觉验证

`language.txt` 只断言字符串，`vgm_ui_test` 用英文；没有证据覆盖 CJK 字体回退、长文案截断、125%/150% DPI 和窄窗口。Linux 缺少 CJK 字体时可能显示方框。

建议加一份人工检查清单，至少在 Windows/macOS/Linux 各截一张中文界面图，检查 100%/150% 缩放和最小窗口宽度；如 harness 的 `shot` 可用，可在 `language.txt` 中留下截图产物，不做像素比较。

## 5. 做得好的地方

- `LanguagePack` 不可变、`shared_ptr<const>` 快照、显式回退链，是正确的并发模型。
- 不修改全局 locale，不依赖 `LocalisedStrings`，窗口刷新边界清楚。
- 外部包扫描有明确上限、排序、隐藏/模板过滤，单文件失败隔离。
- “外部文件缺语言标签 → 警告并跳过”比“猜 zh-CN/zh-TW”稳健；文档也解释了这个取舍。
- 设置保存 ID + 标签，外部文件删除/恢复时行为可预期。
- Language 页的 source/detail/warnings 信息完整，Open Folder/Rescan 形成闭环。
- 测试覆盖了内置包、外部包、回退、缺键数和英文路径；`VGMTOYBOX_SETTINGS_DIR` 隔离了用户设置。
- `i18n-design.md` 对限制、刷新步骤、代码结构和不做的范围写得很清楚，本次评审的大部分结论都能在文档中找到对应设计。

## 6. 文档小建议

- `README.md:183` 说语言包“begins with two metadata lines”，解析器实际允许元数据在任意位置；建议改成“必须包含”，避免外部作者误解顺序是强制的。
- `docs/desgin/i18n-design.md:217` 说主题变化时 `applyStoredSelection` 是 no-op；外部文件缺失时它仍会重设警告，建议措辞改为“通常不改变选择，但会重新校验”。
- 其余格式、回退、文件上限和刷新说明与实现一致。
