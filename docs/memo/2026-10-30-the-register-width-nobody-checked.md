# 一个没查过的位宽，赔进去四轮

- **日期**：2026-10-30
- **对象**：NSF 的 DPCM 采样展示与导出（`NsfBus`、`NsfPlayer`、`WaveExport`）
- **目的**：把这段路上踩的五个坑和三次误判记下来，避免下次用同样的方式再走一遍
- **相关**：`research/2026-10-29-dpcm-sample-display.md`

## 1. 一句话

**`$4013` 在这个模拟器里是 8 位，我按 4 位写，导出的军鼓只有四分之一长。** 其余四个坑都是围着这一个错长出来的。

## 2. 五个坑

### 坑 1：位宽（根因，也是我唯一没有查证就直接用的事实）

**我写的：**

```cpp
pendingDpcmLength = (uint8_t) (val & 0x0F);   // "只有低四位有效"
```

**播放器写的**（`libs/nsfplay/.../nes_dmc.cpp:622`）：

```cpp
dlength = (len_reg << 4) + 1;                 // len_reg = val & 0xff
```

**NotSoFatso 写的**（`NSF_Core.cpp:321`）：

```cpp
case 0x4013: mWave_TND.nDMCLength = (v << 4) + 1;
```

**驱动写 `$4013 = 0x2B`：**

| | 长度 |
|---|---|
| 播放器 / FamiStudio | `0x2B0 + 1` = **689** → 军鼓 688 ✅ |
| 我的捕获 | `0x0B` → **177** → 正好是**底鼓**的长度 |

**所以"军鼓不对"的真相是：我按底鼓的长度导出了一个军鼓。** 那个 177 不是错数，是另一个声音的正确长度——**这就是它能连续四轮骗过我的原因：数字本身是自洽的。**

**教训**：**位宽是外部事实，不是可以推理出来的。** 我手上就有两份源码（播放器的、模拟器的），一份都没看。

### 坑 2：数组大小按"一首曲子的值"定

```cpp
std::array<uint8_t, 193> bytes {};   // 193 是某首歌的 $4013 算出来的长度
```

**而寄存器的范围是 241**（四位时）或 **4081**（八位时）。

**后果**：播放时越界写，进程崩溃。**报的是"播放闪退"，不是"长度不对"，所以两件事看起来无关。**

**教训**：**缓冲大小必须从类型/寄存器的取值范围推，不能从当下观测到的样本值推。** 一个"典型值"写进类型定义，就是把未来的崩溃写进去。

### 坑 3：用"一次播放的长度"当"采样长度"

`$4013` 在四位时代最多 241 字节，而采样是 320/688。**我当时认为必须靠"到下一个 `$4012` 地址的距离"才能知道采样有多长，于是造了一套边界推断。**

**八位之后这套推断完全多余**——寄存器直接给出 689。

**教训**：**当需要"推断"才能得到某个值，先怀疑自己是不是拿错了寄存器。** 推断是对缺失信息的补偿，而缺失往往来自读错，不来自设计。

### 坑 4：`16k+1` 里的那个 `+1`

`$4013` 的长度公式是 `(值 × 16) + 1`。**那个 `+1` 是硬件给每个采样附加的 padding 字节**，这批镜像填 `0xF0`。

**`0xF0` 在字节层面看**像数据**——它不是 `0x00/0x55/0xAA/0xFF` 任何一种填充。所以"去尾部填充"的规则抓不到它，每次都多 1 字节（321 而不是 320）。

**教训**：**填充值有语义，不只是数值。** 判断"哪里结束"要用**产生长度的那个公式**，而不是用对字节内容的猜测。

### 坑 5：`$4012` 的每次写入都算采样边界

驱动会**提前写好下一个采样的地址**再启动。于是"写过的地址"里混进了从未播放的地址，而边界法用它切断了真实采样。

**改成只在 `$4015` 的 0→1 边沿记录**之后，`Entry080` 里那个假的 `$C000` 立刻消失了。

**教训**：**"写过"不等于"用过"。** 任何"根据写入历史推断结构"的逻辑，都要问一句：写入是否等于生效。

## 3. 三次误判：把"看起来对"当成"验证过"

**这三次比五个坑更值得记，因为它们是我主动做的判断，不是漏查。**

### 误判 1：从截图断定"波形是真实采样"

**当时的截图里 DPCM 行确实有曲线。我判断"真实采样取到了"。**

**实际上**：那可能是 `cycleFor` 合成的伪随机图形——两者都是"短促的噪声状曲线"，**在 60 像素宽的窗口里肉眼分不出来**。

**改法**：探针打印 `wave.size()`，看到 `0` 才算证据。**长度是数字，形状是印象。**

### 误判 2：把空框解释成"harness 的假象"

设置页的数值框是白的，我说"可能是截图环境的时序问题"。**实际是白字白底**——一个真 bug。

**改法**：**"什么都没有"和"有但看不见"是两种可能，必须分别排除，不能挑一个解释掉。**

### 误判 3：把错的前提写进断言

```cpp
check (bus.dpcm.length == 17, "and the upper bits of both registers are dropped");
```

**这条断言让 `ctest` 一直是绿的**——它固化的正是那个错误（四位）。

**教训**：**断言不是"记录现状"，是"记录应当"。** 把观测写进断言，就等于给错误上了锁，后面每轮测试都在替它背书。

## 4. 正确的实现，最终形态

```cpp
// 触发那一刻：地址、长度、速率一起锁存
dpcm.start  = 0xC000 | (page << 6);          // $4012，八位
dpcm.length = (lengthReg << 4) + 1;          // $4013，八位，最大 4081
dpcm.bytes  = 触发时刻的一整个 4KB 窗口

// 解码：1-bit delta 积分到 -1..1
level += bit ? 2 : -2;                       // 钳在 -128..127，除以 128

// 收尾：去掉尾部填充，再去掉 16k+1 的那个 padding 字节
if ((length & 0x0F) == 1) --length;

// 导出：float32、无 clm、真实速率（$4010 查表）
```

**不再有边界推断，不再有"按触发次数猜"。**

## 5. 验证到哪一步

| 曲子 | 结果 |
|---|---|
| `Entry080` | `$D200` 320 字节、`$D380` 512 字节，与 FamiStudio 的 `.dmc` 逐字节一致 |
| `fod_snowburnb` | `$C0C0` 689→688（军鼓）、`$C000` 177→176（底鼓），一致 |

**没解决的一件**：`fod_snowburnb` 里还有两个地址（514、388 字节）是 FamiStudio 不列的。**它们确实被播放过、数据也确实不同**，但 FamiStudio 的采样列表里没有。原因在 `NotSoFatso` 的帧级采样里，我没有查实，**不写结论。**

## 6. 如果重来一次

1. **先找这个值在源码里怎么算的**，再写捕获代码。`$4013` 的用法在播放器里就有一行，我没看。
2. **缓冲大小写 `sizeof` 推导的常量**，不写观测值。
3. **断言里只写"应当"，观测值先打印出来看**。
4. **"看起来对"不算验证**。截图只能证明"有东西"，不能证明"东西对"；长度、字节数、哈希才是证据。
5. **当需要推断才能得到一个值，停一下**——大概率是拿错了来源。
