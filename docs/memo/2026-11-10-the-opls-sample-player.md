# OPL 也有采样播放器（2026-11-10）

**为什么写这一篇**：YM2612 的 DAC 折腾了三轮“整首歌该用哪个速率”，而 Y8950 恰好相反——它**有表**，
所以第一版就能按区间导出。把两者的差别写清楚，免得下次又用同一种思路去猜。

## 一、它与 DAC 的区别

| 项 | YM2612 DAC | Y8950 Delta-T |
|---|---|---|
| 地址 | 无，驱动整段流式喂字节 | `0x09/0x0A` 起始页、`0x0B/0x0C` 最后一页 |
| 长度 | 无，靠 `0xE0` 换指针 | stop 寄存器给出 |
| 音高 | 由写字节的速度决定 | `0x10/0x11` 的 DELTA-N |
| 数据 | `0x67` type `0x00`（PCM 银行） | `0x67` type `0x88`（DELTA-T ROM） |
| 可导出的“样本” | 只能按 seek 区域切 | 寄存器已经切好 |

## 二、`05 Impact 151` 实测

- Y8950 @ 3 579 545 Hz，145.6 s，14 053 次寄存器写，**807 次 key-on**（`0x07 = 0xA0`）。
- 三个 `0x88` 块：`romSize = 32768`，偏移 0 / 16384 / 28672。
- `0x08 = 0x00` → 页大小 4 字节；`0x10/0x11` → DELTA-N **0x51F0**；`0x12 = 255`。
- 五个 (start, stop) 页对：0/1023、1024/2047、2048/3071、4096/5119、7168/8191，各 4 KB，
  **正好铺满三个 ROM 块**——这既说明是五件套鼓组，也证明页大小是 4 字节而不是 32。

## 三、速率：72 而不是 144

`fmopl.c` 设 `freqbase = (clock / 72) / rate`；`ymdeltat.c` 的 16.16 累加器每溢出一次消耗**一个 nibble**
（`now_addr++`，`end << 1` 为终点）。所以

```
rate = delta * clock / (72 * 65536)
     = 20976 * 3579545 / 4718592
     = 15 912.5 Hz
```

同一个 DELTA-N 在 OPN 上是 144（它的 DELTA-T 跑在主时钟/2），把 144 用到 Y8950 会让文件只有一半速度。
这正是 DAC 那三轮反复踩的坑，这次先写下来。

## 四、实现

- `OplDecoder`：新增 `kRequirements { 3579545, true, 0x88, 1<<24, false, false }` 与 `attachMemory`；
  跟踪 `0x08`、`0x09/0x0A`、`0x0B/0x0C`、`0x10/0x11`、`0x12`；key-on 时解码区间前 4 096 字节进
  `state.wave`，`sampleRate` 用上面的公式。
- `VgmReplayer`：`DEVID_Y8950 → slotFlags = 1`，`reset` 读 `ChipConfig::flags` 的 bit 0 打开 `adpcm`。
  **以前实时路径用默认构造的 `OplDecoder`（`adpcm = false`），这颗芯片根本没有第 15 行。**
- `collectY8950Samples`：一段区间一个文件，`adpcmB4`（与 OPN Delta-T 共享 `OpnAdpcmB.h`），
  30 s 上限；`05 Impact 151` → 五个 `y8950adpcm_*` 文件，8 192 点、15 912.5 Hz。

## 五、边界

- 只做外部内存播放（`0x07` bit 5，值 `0xA0`）；CPU 喂数据（`0x80`）不收集。
- `0x12` 音量不参与导出（导原始 nibble）。
- 循环位（`0x07` bit 4）只导第一遍。
- 行的波形是区间前 4 096 字节；`stop` 指向 ROM 末尾的驱动不会让一行变成 2 MB 解码。

## 六、验证

- `testY8950AdpcmRow`：8 192 点、速率 15 912.5、与 `opn::deltaT::decode` 逐值相等。
- `pcm-y8950.txt`：5 个样本 + 首个名字。
- `assert engine.wave.14 == 8192`：实时快照里第 14 行确实拿到了波形（截图在 headless 下时序不稳，
  这一条比截图可靠）。
