# GA20：0x00 表示停止，以及一个会变空白的格子

> 第三颗采样芯片。芯片本身是三颗里最省事的——没有采样表、没有 bank、没有压缩格式——但交付前
> 暴露了两个属于**显示层**的问题，都不在芯片里。

## 1. 芯片事实

| 项 | 事实 | 来源 |
|---|---|---|
| 声道 | 4 | `channel[4]` |
| 寄存器 | `reg & 0x1F`，`channel = reg >> 3`，低 3 位：0/1 起始地址、2/3 结束、4 速率、5 音量、6 控制 | `irem_ga20_w` |
| 起始地址 | **16 字节单位**（`data<<4` / `data<<12`），20 位 | L265-270 |
| 结束地址 | **核心从不读**——写了也白写 | 全文无 `ch->end` 读取 |
| 起播 | 控制寄存器 **bit1**（`data & 2`） | L291-298 |
| 数据格式 | **8 位无符号，`0x80` 中点**：`rom[pos] - 0x80` 存入 `int8_t` | L177 |
| 采样结束 | **`0x00` 即结束**（`if (!rom[pos]) play = 0`），该字节不发声 | L174-175 |
| 速率 | 设备速率 = `clock/4`；每字节占 `256 - rate` 个设备样本 | L367 / L282 |
| ROM 块类型 | `0x93` | `vgmplayer.cpp:371` |
| VGM 命令 | `0xBF` | `vgmplayer_cmdhandler.cpp:214` |

**实测**（`11 Redtailed Cat`，17 首素材之一）：芯片构成 = **YM2151（FM）+ GA20（PCM）**，
12 行 = 8 FM + 4 PCM。ROM 三个 `0x93` 块声明 512 KB、实供 49 KB（`0x63320` 起），
`0x00` 占比 0.1%（31+20+1 = 52 个），正是一段一个结束符。

## 2. 与 K007232 / OKIM 相比省掉的三件事

1. **没有 bank**：地址就是地址
2. **单芯片**：VGM 只有一个 GA20 时钟字段，不存在双芯片合并
3. **解码器已在 key-on 时锁存** `latchStart`，行与收集器同源，不需要"序列收尾"那套

速率仍按 OKIM 的教训走 `PLR_DEV_INFO::smplRate`（此处 `= clock/4`，与算术一致，但只取设备值）。

## 3. 两个显示层问题（都不是芯片问题）

### 一、探针把 `null` 和 `0 pts` 打印成同一个数

调试时我看到 GA20 的行 "wave=0"，据此判断解码器没产出波形。实际是**探针把两者打印成了同一个
`0`**，而真正为 0 的是 **YM2151** 的行——我把行号认错了（`[0..3]` 是 GA20，`[4..11]` 是 FM）。
改成 `wave=null` / `wave=N pts` 两种输出后一眼可辨。

**教训**：诊断工具本身的歧义会制造假象，比没有诊断更贵。

### 二、通道空闲时格子里什么都没有，无法拖拽

行画的是**当前**状态；采样一停，`wave` 就为空，格子变空白。而 GA20 的采样极短
（2000 字节 @ 34 kHz ≈ 60 ms），几乎全程都在"空档"，所以这个缺陷在它身上最明显——
用户的截图就是这样：Ch3 是空白框。

**修法（全芯片，一处）**：在 `LibvgmTrackPlayer::captureState` 里按 `(设备, 通道)` 锁存
**`(wave, rate)` 这一对**，当前没有就回放上一次。要点：

- **必须成对**。只留波形、速率归零，`WaveExport::canExport` 仍会拒绝导出——格子看着能拖，拖出来是废文件。
- **`active` 不动**，于是保持态用暗色画（`active ? 0.9 : 0.35`），不假装在响。
- **跳转与换歌时清空**：跳转后上一个采样属于已经离开的位置。
- 静音**不**清空：静音不改时间位置，清掉反而让你在静音状态下无法拖拽。

实测（`-4`，`active=0` 的行仍带完整的一对）：

```
t=15.0  [0] GA20 Ch1 wave=2126 pts rate=17209.3 active=0
        [1] GA20 Ch2 wave=7286 pts rate=34418.7 active=0
```

## 4. 无头测试的边界（诚实记录）

新加的 `assert engine wave.<n>` 在**应用 harness** 里读到 `0 of 0 channels`——那里的引擎没有
显示状态的来源（键盘页用的是另一条 probe 路径）。所以：

- 该断言保留（它会如实报出通道数），但**当前无法用它验证保持行为**
- 保持的实际验证靠探针 `-4`（手工工具，不进 ctest）
- 若要让它在 ctest 里成立，需要把键盘页的 probe 播放器接进 harness —— 未做
