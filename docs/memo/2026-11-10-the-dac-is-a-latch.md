# DAC 是一个锁存器（2026-11-10）

**为什么写这一篇**：DAC 相关的东西改了三版速率（13 799 → 22 050 → ×1.637 → 按区域），每次都能解释自己，
但放在一起就越看越乱。原因不在实现，而在**没有先把机制写下来**。这一篇只写机制与边界，不写实现细节。

## 一、机制

YM2612 的第六通道不是采样播放器，是一个 8 位锁存器：

```
Z80 ──字节──► [0x2A 锁存] ──► DAC 输出（保持到下一次写）
```

- 写什么 = 波形；
- 写得多快 = 音高；
- 写多久 = 时长；
- 不再写 = 保持最后一个电平（所以驱动要持续写 `0x80` 让 DAC 停在中点）。

芯片本身没有地址、长度、循环位、速率寄存器。所有这些“样本”的概念都存在于**驱动**里。

VGM 记录的内容只有：

| 命令 | 含义 |
|---|---|
| `0x80-0x8F` | 取 PCM 银行的下一个字节写进 `0x2A`，再等 n 个采样 |
| `0x52 0x2A xx` | 直接写一个字节 |
| `0xE0 offset` | 把银行读指针挪到 offset（驱动“从表里第 N 项开始播”） |
| `0x2B bit7` | 打开 DAC |

## 二、银行是表，不是样本

银行（`0x67` type `0x00`，ROM 形式 `0x80`）是一整块没有地址的字节。驱动用 `0xE0` 移动读指针，**这些去重
偏移就是它的采样表**；两个偏移之间的字节就是一个样本的素材。

实测（四首 Sonic 1）：

| 曲子 | 区域数 | 各区域速率 |
|---|---|---|
| 02 Green Hill | 5 | 8.0 / 8.0 / 23.2 / 23.2 / 8.1 kHz |
| 03 Marble | 4 | 23.2 / 8.0 / 7.9 / 23.0 kHz |
| 04 Spring Yard | 4 | 22.9 / 22.8 / 7.9 / 7.9 kHz |
| 05 Labyrinth | 3 | 16.0 / 12.1 / 7.9 kHz |

同一区域每次被访问的速率**非常稳**（96 次访问差异 <0.02 tick）。**同一首歌里 8k 和 23k 并存**，所以
“整首歌一个速率”这个前提本身是错的。

## 三、三次错过的速率

| 用过 | 它其实是 | 为什么错 |
|---|---|---|
| 13 799 Hz | 整条流的均值 | 把 23k 的鼓、8k 的鼓、1–2 tick 的静音混在一起 |
| 22 050 Hz | 响亮字节间隔的中位数 | 只是把分布切成两半，仍是全曲一个数 |
| 22 050 × 1.637 | 一记军鼓对齐得到的经验值 | 换歌即错，不是格式属性 |

现在：**区域 + 区域内间隔均值**。均值而不是中位数，因为间隔是抖动的（5.5 tick 写成 5 和 6），中位数会
把 5.5 量化成 8 820。

## 四、静音为什么在流里

DAC 保持最后一个电平，驱动要让输出停在中点就必须持续写 `0x80`。这些静音字节写得快（1–2 tick），因为
它们的节奏不影响声音，只影响“空多久”。这正是整条流均值被拉低的原因。

## 五、仍不能还原的四件事

1. **名字**：文件里只有偏移，没有“底鼓/军鼓”；
2. **循环点**：驱动自己跳回去，`0xE0` 不区分“重播”与“循环”；
3. **移调**：驱动若为音高改变写入速度，只会表现为“这个区域速率不同”，原始录音速率无法还原；
4. **静音入口**：Green Hill 的 `0x0000` 是 96 字节的停止用素材，5 个区域只有 4 个出声；过滤阈值没有
   数据支撑（该段只有 31% 落在 ±2 内），暂时不猜，保留原样。

## 六、判据

以后遇到“DAC 导出速率不对”，按顺序问三个问题：

1. **单位是什么？** 不是区域就没有唯一答案；
2. **速率是哪个区域量的？** 全曲统计量一定错一半；
3. **参照物是文件里的同一段字节吗？** 若不是（另一版音源、被移调过的样本），差值属于参照，不属于文件。

（可视化那行的速率是“此刻多快”的滑动均值，与文件的区域速率回答的是不同问题，不必对齐。）

## 七、同一天的第二版：区域也不对，单位是 run

区域模型（相邻 `0xE0` 偏移）只活了一天。参考 `vgm2fur` 后实测：驱动会**跨偏移连续播**——Marble 的
`0x0A80` 一次播 1 693 字节、Labyrinth 的 `0x0000` 一次播 3 808 字节，所以偏移不是边界。

现在的单位是 **run**：`0xE0`（正在播/未播）开始一个，字节间隔 ≥512 采样（11.6 ms）切开；速率
`tickRate × length ÷ duration` 整数除法，`(start, length)` 首次速率胜出。`02 Green Hill` 得到 8 个样本
（5 398 / 1 584 / 3 810 / 3 808 / 116 / 96 / 1 488 / 93），与 `vgm2fur` 写进 `.fur` 的 `SMP2` 逐字节、
逐速率相同；导出格式因此改成 `pcm8Signed`（DAC 的静音是 `0x80`）。

细节见 `docs/research/2026-11-10-vgm2fur-dac-runs.md` 与设计文档 §9.20。
