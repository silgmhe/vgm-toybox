# OPN 的 ADPCM-A：六个采样声部，和一行都没出现的原因

2026-11-08。第七颗采样芯片，素材两首（`04 Stage 1`、`07 Stage 2`，均为 YM2610）。

## 一、我一开始的判断是错的

我看端口 1 的写入直方图，发现没有 `0x00`（key-on）、没有结束页写入、`DELTA-N` 为 0，
于是结论是“这两首没用 ADPCM，打击乐全在 FM”。**用户一句“这两首 ADPCM 通道应该有的有
音符的”把结论推翻了。**

真正的原因在表结构，不在素材：`ChipBuffer::makeDecoder()` 是 `std::make_unique<Decoder>()`，
而四种 OPN 设备共用一个 `ChipBuffer<OpnDecoder>` —— 全部按**默认 variant（YM2612）**建。
YM2610 的 13 个声部因此只列出 7 行（6 FM + DAC），ADPCM-A / ADPCM-B 的行**根本不存在**。

修法：型号随 `ChipConfig::flags` 传进 `reset`（1=YM2203、2=YM2608、3=YM2610、5=YM2612）。
修完 `04 Stage 1` 由 7 行变 11 行、`07 Stage 2` 由 7 行变 14 行，ADPCM-A 各行随鼓点亮。

**教训**：写入直方图只能证明“某个地址没被写”，不能证明“这个声部没响”。唯一可信的判据是
**已经实现的行**。

## 二、寄存器与格式（`fmopn.c`）

| 端口 1 偏移 | 含义 |
|---|---|
| `0x00` | key-on/off，bit7 = 全停，bit0-5 = 各声道 |
| `0x01` | 总音量 TL（`(v & 0x3F) ^ 0x3F`） |
| `0x08+c` | 各声道电平/pan |
| `0x10+c` / `0x18+c` | 起始页 低/高（字节地址 = 页 << 8） |
| `0x20+c` / `0x28+c` | 结束页 低/高，`+0xFF` |

解码：4 位、高半字节在前；`steps[49]`（16,17,19,…,1552）× `step_inc[8] = {−16×4,+32,+80,
+112,+144}`；累加器 **12 位回绕**后符号扩展；每 nibble 一个采样。

## 三、第二个 bug：速率快 3 倍

`channelState` 里我写的是 `clock / 144`（55 555.6 Hz），用户听出“音高明显偏高”。
正确的是 **`clock / 432` = 18 518.5 Hz**：

- 核心 key-on 注释里的公式是 `(1<<ADPCM_SHIFT) * freqbase / 3.0`（值被预先算好，那行保留）；
- Neo Geo 的 ADPCM-A 鼓本就按 18.5 kHz 录制；
- 除以 3 恰好是 **19 个半音**，与“明显偏高”一致。

## 四、导出

`collectOpnAdpcmSamples`：走端口 1，key-on 时锁存 `start..end`，取 `0x82` 的 8 MB 镜像，
用 `SampleFormat::adpcmA4` 解码，速率取 `clock/432`。

去重的两次尝试都留下数据：

| 做法 | 结果 |
|---|---|
| 什么都不并 | 94 / 91 个文件，`0x27600_00DFF` 与 `0x28400_00DFF` 这类相邻页副本并存 |
| 间隙 ≤ 0x100 就并 | 23 / 25 个，但出现**一个 44 秒的文件**（连续页串成整 bank） |
| 间隙 ≤ 0x100 且 ≤ 16 KB，再按 FNV 内容去重 | **90 / 83 个**，最长 3.0 / 3.4 秒 |

第三种是交付的版本。计数只从 94 降到 90，因为剩下的区间在 ROM 里彼此隔得很远、字节也不同——
按“同一段录音”的标准不该合并。要进一步减少只能做**内容指纹聚类**，会有误伤相似鼓的风险。

## 五、没有解决的

1. **ADPCM-B（Delta-T）没有接 ROM**：两首素材里它从未启动（无 START 位、`DELTA-N = 0`），
   没有可验证对象；`setAdpcmBRom` 与 `0x83` 镜像都在，但没有调用点。
2. **ADPCM-B 行个别曲目仍可能显示波形**：ADPCM-A 行范围按 `fmCount..channelCount-1` 取，
   遇到 FM 声道数不为 6 的变体会多算一行，未修完。
3. 未做指纹聚类，同一记鼓的长短两版可能各占一个文件。

## 六、可复用的三条

1. **“共用解码器 + 默认构造”是隐藏的型号 bug**：一行 `make_unique<T>()` 让四种芯片都成了
   默认型号，而且只在“行数不对”时才看得出来。
2. **采样芯片的速率一定要对表**：144 与 432 差 3 倍，听起来就是“高了一个半八度”，很容易
   被误当成解码错误去查格式。
3. **合并的边界要用数据定**：0x100 是芯片的页粒度，但只用它合并会串出 44 秒的整 bank；
   加一个 16 KB 上限才既收回重触发、又不把不同采样粘在一起。
