# Mikey：没有表，只有一台 LFSR；以及它暴露的两个缺陷

> 第八颗芯片。芯片本身不难，难的是它把两个**此前一直存在、但没人踩到**的假设同时点亮了：
> 加载路径的复杂度，和"`wave == nullptr` 只意味着采样结束了"。

## 1. 芯片事实

| 项 | 事实 | 出处 |
|---|---|---|
| 声道 | 4（这批曲子里 ch1 全程无写入） | `mikey.c:184` |
| 输出 | 12 位寄存器，`reg = ((reg<<1) & 0x0FFE) \| (parity^1)`，`out = reg&1 ? +vol : -vol` | `mikey.c:490-503` |
| 抽头 | FEEDBACK 低 6 位 + 高 2 位左移 4；外加 CTRLA bit7 | `mikey.c:420`、`442` |
| 积分 | **CTRLA bit5**（`0x20`）。音量寄存器是纯 signed byte，没有"bit5 = integrate"这回事 | `mikey.c:372`、`414` |
| 步进率 | `clock / ((backup + 1) * 2^(shift + 4))` | `mikey.c:355` |
| 采样率 | `clock / 16`（设备自报，仅用于混音） | `mikey.c:971` |

**它不是波表芯片。** 输出是一台由定时器驱动的 LFSR：同一组 (seed, taps, integrate) 决定一条
周期序列。实测周期：

```
taps 0x07 -> 4 步        音调，4 点方波（占空比 2:2 或 1:3）
taps 0x2C -> 62 步       有音高的噪声纹理
taps 0xEC -> 3556 步     噪声，没有可画的周期
```

所以音高 = 步进率 ÷ 周期长度。**旧代码假设"周期 2"**，于是所有音高都差一个八度/若干倍。

## 2. 缺陷一：加载从秒开变成 2 秒

### 现象

`Mikey` 曲目打开约 2 秒；同一目录的 K005289 是 0.16 秒。

### 原因

收集器在**每一条**寄存器写入之后都调用 `buildPattern()`。这些曲子每条有 **12 475 – 23 510**
条写入，而每次调用要：

1. 用一个 `std::map` 记录已见状态（最多 4096 次插入）；
2. 一直走到状态重复为止——对 `taps=0xEC` 是 **3556 步**；
3. 然后因为周期超过 512 被丢弃。

也就是说：**为一个注定被丢弃的结果，付了三千步 + 三千次树插入**，重复一万次。

### 修法

| 改动 | 作用 |
|---|---|
| 按 `(seed, taps, integrate)` **记忆化** | 重复写入（同一 taps 反复写、同一 seed 反复装载）不再重算 |
| 探测上界 **4096 → 576** 步 | 周期 > 512 的结果反正要丢，多走三千步只为"证明它长"是纯成本；576 = 512 + 64（移位寄存器的暂态最多一个位宽） |

```
1872 ms  ->  180 ms
```

### 教训

**收集器运行在加载路径上。** 写"每个事件做一点小计算"时，先问一句：事件数是十级还是万级？
万级时任何常数都变成了秒。判据不是"单次成本小"，而是 **O(事件) 还是 O(事件 × 每事件成本)**。

## 3. 缺陷二：噪声段仍然显示旋律的方波

### 现象

用户："ch4 既噪声也有旋律，但波表总是类似 PWM；噪声波表好像在 ch1。"

### 分析（先证伪了一半）

实测每通道的 taps 写入次数：

```
ch1  一条写入都没有        <- 所以"噪声在 ch1"不成立，ch1 全程静音
ch2  0x07 x3660
ch3  0x07 x4280   0x2C x16    0xEC x12
ch4  0x07 x272    0x2C x26    0xEC x226     <- 噪声主要在这一条
```

也就是说 ch4 **确实**同时承担旋律与噪声，用户的听感是对的、位置的猜测不对。逐时刻扫描行后
定位到两个真正的缺陷：

### 缺陷 2a：保持逻辑套错了对象

噪声段我们返回 `wave = nullptr`（无周期可画）。共用层的锁存（ADR-007）规则是"当前不完整就回放上一对
`(wave, rate)`"，于是**上一段旋律的 4 点方波被画在了噪声段上**——看到的 PWM 与听到的噪声来自同一
通道的不同时刻，两边都没错。

判据缺的那一半是 `gate`：

```cpp
const bool sounding = chipState.gate || chipState.released;
if (playing)                       { 记录 }
else if (held.wave && !sounding)   { 回放 }   // 只有空闲才回放
```

### 缺陷 2b：音符表编造了音高

空闲帧稳定显示 `note=107 hz=3937.4`。算一下就知道来源：`3937.4 = 16e6 / (2 * 127 * 16)`，
正是**旧公式**（除以 2）在 `backup=126, shift=0` 时的值——音符表把"步进分频"当成"音高分频"，
再按周期 2 除以二，于是任何一个残留的 period 都能"算"出一个音符。

修法：`MikeyDecoder::Impl::Table::noteFor()` 直接返回 `-1`。这颗芯片的音高**只有**真实周期
能给出，表不该有答案。

### 验证

```
14 s（噪声段）: wave= null rate= 0.0 note= -1 active=1      <- 诚实
 3 s（旋律段）: wave= 4 pts rate= 261.5 note= 36 hz= 65.4   <- rate/4 = hz
```

### 教训

**`wave == nullptr` 有两种含义**：采样结束了（可以回放上一次），以及**正在响但没有周期**（不能回放）。
共享层的判据必须把两者分开，否则为一个芯片做的修好会悄悄改变另一个芯片的语义——这次改的是
`LibvgmTrackPlayer::captureState`，一处改，八颗芯片都在它的射程内，所以回归必须全跑。

## 4. 其余实现要点

- LFSR 生成器抽成 `chips/MikeyPattern.h`，**解码器与收集器共用**：形状只有一个答案。
- 通道类型返回 `wavetableWave` 而不是 `sn76489Square`：后者会让显示与导出按 `duty` 合成一个
  50% 方波，把 4 步周期里真实的占空比丢掉。
- 没有周期时返回 `nullptr` 而不是空 vector：空 vector 在行里显示成 `0 pts`，看着像解码器坏了。

## 6. 可复用的清单（第八次）

1. **先判断"这颗芯片有没有表"**。Mikey 没有：它的波形是递推出来的，照抄前两颗的"读样本/读表"会一无所获。
2. **收集器属于加载路径**：先算清事件数，再决定是否在事件里做重活。
3. **共享层的判据要能区分"没有"的两种含义**（结束了 / 正在响但无形状），改它要跑全量回归。
4. **音符表不是万能兜底**：当分频器不是频率时，返回"无音符"比编一个数更正确——后者会稳定地骗过所有人。
