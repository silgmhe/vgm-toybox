# 4-op 挂起了：规则已证清，卡在“配对后静音”

> 2026-11-28。用户决定：**先记录，等找到用 4-op 的曲子再回来。**
>
> 这份备忘录的目的不是讲故事，而是**让下一次回来能在十分钟内接上**，而不是重新踩一遍。

## 一、为什么挂起（一句话）

**没有任何素材能验证。** 180 首 OPL3 曲子（`test_file/ymf262` 3 首 + `G:\VGM\Tokimeki_Memorial…` 177 首）
**没有一首**的 `0x104 ≠ 0`，即没有一首启用 4-op 配对。在“找不到能响的对照”的状态下继续调寄存器，
就是 OPL2 鼓那四轮的原样重演。

## 二、已经证实的规则（都带行号，可直接引用）

| 事实 | `nukedopl3.c` |
|---|---|
| `0x105` bit0 = `newm`，**同时**是第二 bank 的开关；`newm == 0` 时高字节寄存器被清零 | `:1450`, `:1463` |
| `0x104` bit0-2 → 通道 `0,1,2`；bit3-5 → `9,10,11`；配对对象是 **+3** | `:1103-1113` |
| 配对后 `chtype`：第一个 `ch_4op`，第二个 `ch_4op2` | `:1112-1113` |
| key-on 只写**第一个**通道的 `0xB0`，`ch_4op` 一次 key 四个算子（经 `pair->slotz`） | `:1051-1061` |
| `ch_4op` 的 `alg = 0x08`，在 `SetupAlg` 里**提前 return**；布线由 `ch_4op2` 做 | `:988-1001`, `:907` |
| `pair` 指针在复位时就按 `channum % 9` 建好，不是 4-op 时才建 | `:1381-1388` |

**结论：写顺序必须是 `0x105` → `0x104`**，否则 `0x104` 会被当成 bank0 的 `0x04` 丢掉（`:1450`）。

## 三、四次测量（同一批四个算子，全部实测）

| 构造 | 峰值 |
|---|---|
| 四个算子**不配对**（两个 2-op 声部） | **0.1250** |
| 配对 + `0xC0 = 0x00` + 只 key 第一个通道 | **0.0000** |
| 配对 + **也** key 第二个通道（`0xB3`） | **0.0000** |
| 配对 + `0x105/0x104` 放在 `0xC0` **之前** | **0.0000** |

**配对本身把输出变成零，且与 keying 方式无关。**

## 四、回来后的第一步（不要跳）

有了 `0x104 ≠ 0` 的曲子，**按这个顺序**做，不要先改代码：

1. **先确认它真的配对**：解压 → 找 `0x5F 04 xx`，`xx ≠ 0`；同时确认 `0x5F 05 01` 出现过。
2. **打印该曲的 `0x104` 值**，算出启用了哪几对（bit0-2 → 通道 0-2，bit3-5 → 9-11）。
3. **在核里加一行打印**（这是上次 OPL2 鼓真正解决问题的动作）：在 `OPL3_ChannelKeyOn`（`:1051`）里打出
   `ch_num / chtype / alg`，再在输出汇总处打出该通道的 `out[0]` 指针与值。
   —— **先看“这四个 slot 有没有被 key、输出有没有被读到”，再谈寄存器内容。**
4. 只有第 3 步确认了 keying 与输出都在，才回头怀疑**四个算子该放在哪几个偏移**
   （我的假设是 `0,3` 与 `8,11`；这条从未被证实过）。

## 六、别忘的两个已修事实（它们比 4-op 更有价值）

1. **`0x105` 必须先于 `0x104`**（上面第 2 节）。
2. **寄存器的端口由它自己的 bit8 决定**，不是由 patch 第一条决定（`b60d8a8`）。
   这条修好后，**OPN/OPM 的第二端口寄存器**也第一次真正到达了核。

> 在有对照组之前，任何“我觉得应该这样连线”的修改都无法判定对错——**那正是上次烧掉四轮的东西**。
