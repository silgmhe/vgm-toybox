# OPL2 的鼓到底是怎么修好的

> 2026-11-24。用户的原话是「你好像莫名其妙就把 OPL2 的鼓做出来了，甚至你自己都不确定」。
>
> 这句话是准确的。**成功不是因为我某一步突然想对了，而是因为我把一次观测放进了黑箱内部。** 这篇把过程摊开，指出哪一步是转折，以及在那之前每一轮为什么白费。

## 一、结论先行

**关键的一步是：在核的 `0xBD` 写入处理里放了一行打印，然后跑两条路径对比次数。**

```
曲子经 libvgm 播放：   [BD] 出现 67 701 行
我们的驱动渲染鼓：     [BD] 出现 0 行
```

那一行输出把「寄存器组合是否正确的无限搜索」变成了一个布尔问题：**写入有没有到达核。**

答案是**没有**。于是问题从「OPL2 的鼓需要哪些寄存器」变成了「为什么我们从来没写过 `0xBD`」——而后者的答案是一行代码：**OPL2 的节奏方言当时根本不存在**（它在之前的一次回退里被删掉了）。补上方言之后，同一个 patch 立刻出声：

```
[load] oneshot 1 model 7 dialect opl2-rhythm regs 10
[BD] val 20
[BD] val 30
TEMP opl2 drum peak 0.2500
```

**在任何测量之前，我的每一次尝试都只是猜测。**

## 二、时间线：五次尝试，四次错在同一个习惯

| # | 我的假设 | 怎么测的 | 结果 | 真正的错误 |
|---|---|---|---|---|
| 1 | 鼓由 9 条参数寄存器合成 | 手写一组 patch 灌进核 | **peak 0.0000** | 寄存器值是我编的，不是曲子写的 |
| 2 | 每个鼓用自己的槽位 | 按「BD=ch6、SD=ch7」分别构造 | **全 0** | 槽位号与寄存器偏移是两套编号 |
| 3 | 重放曲子的真实写入序列 | 解压 `.vgz`，把 `0x5A` 命令流原样灌入 | **rms 0.28，响了** | 只是证明了核有能​力，没有证明我们的路径通 |
| 4 | 缺某个寄存器或顺序 | 换顺序、换值，反复试 | 全 0 | **仍然在黑箱外面猜** |
| 5 | **写入可能根本没到核** | **核内打印 + 两条路径对比** | **67 701 vs 0** | **这一轮才第一次看见事实** |

**第 1–4 轮的共同错误**：所有观测都在核的**外面**。峰值为 0 时，我无法区分「寄存器内容错」「写入没发生」「触发位不对」三种情况——**它们的外部表现完全相同**。

**第 3 轮的价值**在于给出了一个「已知能响」的基准，但它是灌进核里的，**绕过了我们的驱动**，所以我误以为机制已经验证过。

## 三、转折点为什么有效

关键在于**对照**：同一条写入、同一个核，一个走 libvgm 自己的播放器，一个走我们的 `FmVoiceDriver`。

```
曲子路径  → 67 701 次 [BD]     （已知能出声）
我们的路径 → 0 次 [BD]          （被测对象）
```

- **同一内核**：排除「这颗核不支持鼓」
- **同一条寄存器**：排除「写错地址」
- **只差一层驱动**：把范围压到唯一剩下的地方

**判据的形状也对**：不是「音量对不对」（连续量，噪声大），而是「有没有发生」（布尔，不会骗人）。**先用布尔量定位层次，再用连续量调数值。**

## 四、第二个关键：两套编号

写入到达核之后，剩下的错误在**寄存器内容**上，而它也有一个确定的答案——`regbase2modop`（`adlibemu_opl_inc.c:89`）：

```
0,1,2,0,1,2,0,0,3,4,5,3,4,5,0,0,6,7,8,6,7,8      ← 寄存器偏移 → 核的算子基号
```

由此得到**bank 内的真实排布**：

| 偏移 | 16 | 17 | 18 | 19 | 20 | 21 |
|---|---|---|---|---|---|---|
| 算子 | ch6 调制 | ch7 调制 | ch8 调制 | **ch6 载波** | **ch7 载波** | **ch8 载波** |

**三个调制器在前，三个载波在后**，而解码器内部的槽位号是 `(ch/3)*6 + ch%3 + 3*op`。两者在 13/15/17 上错开一到三位——**这就是「只有 Ch10 对」的原因**。

配合鼓的混音（`adlibemu_opl_inc.c:1468-1470`）：

```c
chanval = (OPL->op[7].cval + OPL->op[7+9].cval)*2;   // ch7：SD / HH
chanval = OPL->op[8+9].cval*2;                       // ch8：CYM
```

才能把「哪几个算子」翻译成「哪几条寄存器」。

## 五、我这次还犯了三个可以被复用的错误

**① 用「听起来对」代替「证明了」**
第 3 轮重放有声音，我就以为机制验证完毕，其实我验证的是**核**，不是**产品路径**。**能证明 A 的实验不能证明 B。**

**② 把「已经改过的代码」当成「已经在跑的代码」**
`0xBD` 从不出现，真正原因是方言被回退掉了。我在那个状态上继续做寄存器实验，结论必然是「怎么换都不响」。**测量之前先确认被测对象存在。**

**③ 用新记法重新推导一个已经正确的表**
修完鼓之后我又「按偏移」重写了一版映射，把 BD 写成 `{16,20}`（ch6 调制 + ch7 载波），截图立刻全变平，只好回退。**原来的表是对的——我只是用另一种记法抄错了。**

## 六、可复用的顺序

```
1. 这个信号有没有到达目标？        ← 布尔，放打印在边界上
2. 到达了，内容对不对？            ← 打印实际字节，与真值逐条比
3. 内容对了，为什么不出声？        ← 才轮到寄存器知识
```

**我这次把顺序倒过来做了四轮。** 每一轮都在第 3 步里找答案，而问题一直在第 1 步。
