# 2026-10-20 YMZ280B：搁置，以及为什么（M3 的第二颗）

## 结论

**YMZ280B 暂不进入 MIDI 覆盖面**，解码器留在 `plugin/Source/chips/Ymz280bDecoder.{h,cpp}`，但**不进 ctest、不计入 §11.2 的 54 项**。M3 只按 YMF271 这一颗来验收。

## 依据（不是“做不出来”，是“做出来也没有意义”）

1. **芯片本身是 8 个独立 PCM/ADPCM voice**（手册 YMZ280B.PDF 的规格页；MAME `ymz280b.cpp` 与 libvgm 的核同源）：`voice = (reg >> 2) & 7`，每 voice 有音高（播放速率）、总音量、pan、起止地址、key-on 位。
2. **但 vgmrips 上这颗芯片的成套录音，实际上是一条长样本**。用 `test_file/ymz280b/` 的两首核对：
   - `01 Hot Hips (Beach Court).vgz`（70 s）与 `02 Spirit of Fang -Gouga- (Player Select).vgz`，MDPlayer 的输出同样只有一路；
   - 我们这边（解码器改成直写之后）`vgm_mixer_test --notes`：8 条轨里只有 **Ch4 一个音符（0.00）**，整曲渲染 `peak 0.9862 / rms 0.1933`；
   - 用 `vgmdump5d.py`（临时脚本）走查 `01` 的 87 条 `0x5D` 写：`aa` 是**寄存器号直写**（`0x0D 0x20`、`0x6C 0xBD`、`0x4C 0x04`…），没有 per-note 的 key-on 序列。
   也就是说：这些曲目把整首曲子当成一个 sample 在放，天然只有一路、几乎不产生“音符”。（早于直写修正的那次测量是 8 条轨全 0 notes，那是 latch 假设的后果，不是数据本身的性质。）
3. 既然如此，`[13]`（“有声轨必须报音符”）对这颗芯片没有可断言的内容：给它写 one-shot 触发器，只会得到“整曲一个音符”，这条断言即便通过也不证明任何东西。

## 已经落地的部分（保留，作为将来重启的基础）

- `Ymz280bDecoder`：8 voice、`reg & 0xE3` 分四组（0x00 音高/键控/音量/pan、0x20/0x40/0x60 起止地址）、`0xFF` bit 7 = key-on enable、bit 6 = ext mem enable（必须为 0，ROM 走数据块）、80 ms 门限的 one-shot、音量 0 不出音符；
- 单测（`vgm_chip_test`，9 条 YMZ 检查全绿）：一次 key-on = 一个 C4、寄存器 `0x05` 落 voice 1、level 0 不出音符、PCM voice 落鼓键、`5D <reg> <val>` 直写；
- 接线：`midiCapabilityFor` 里 8 通道标 `oneShot`，`MidiSequenceBuilder` 的 `case 0x5D` + `flushDecoded(ymz, 16934400, …)`；
- **教训（这条比代码值钱）**：VGM 的 `0x5D` 是 `aa dd` 的**寄存器直写**，不是硬件那种“偏移 0 选寄存器、偏移 1 写数据”的两步对。最初按 latch 实现，真实曲目因此 0 音符。凡是“手册说串行/锁存接口”的芯片，都要先用真实文件 dump 一遍再写解码器。

## 重启条件（任意一条满足就可以捡回来）

1. 拿到一首**真的按 voice 触发**的 YMZ280B rips（多路、有 key-on/key-off 序列），先用 `vgmdump5d.py` 确认 `0x01 + 4k` 的写里出现 bit7 翻转；
2. 或者等 **M4 的“步进/采样率→音分 + 根音”** 工具落地：那时可以把播放速率映射成真正的音高，即使整曲是一个 sample，也能作为“一个长音 + 弯音”产出有意义的事件；
3. 在那之前，生成资产 `plugin/Tests/assets/ymz280b.vgm`（`make_ymz280b_song.ps1` 生成，改为直写后实测 4 个 C4、`peak 0.5914 / rms 0.2835`、solo 与 mute-others 一致）只有“证明 0x5D 解码链路能出音符”的价值，不足以作为端到端用例——它**没有**注册进 ctest。

## 复核方式（三条命令，30 秒）

```bash
build/plugin/vgm_chip_test.exe                                   # 9 条 YMZ280B 检查
build/plugin/vgm_mixer_test.exe plugin/Tests/assets/ymz280b.vgm 2 44100 --notes
build/plugin/vgm_mixer_test.exe "test_file/ymz280b/01 Hot Hips (Beach Court).vgz" 4 44100 --notes
```

第二条应打印 Ch1 的 4 个 C4 与 `peak 0.5914 / rms 0.2835`，第三条应打印 Ch4 的 1 个音符（0.00）。

## 顺带记录（与本芯片无关）

- （已排除）此前看到“solo 后 `rms 0.000000`、整曲却有 0.19”，一度怀疑 8 voice 器件的按轨隔离没接上。直写修正后在同一资产上复测：solo `rms 0.283477` 与 mute-others `0.283477` 一致，`[8]` 通过——那次静音是 latch 解码下“发声的 voice 与轨道对不上”造成的假象，**隔离逻辑本身没问题**；
- `.vgz` 里 `0x67` 的 ROM 块长度必须等于 `8 + 样本长度`（libvgm 在 `_filePos += 0x07` 之后按长度字段前进），否则后续命令整体错位一条。这条已写进 `make_ymz280b_song.ps1` 的注释。
