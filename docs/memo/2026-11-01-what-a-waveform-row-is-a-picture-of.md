# 一行波形到底在画什么：四次返工

> 分支 `feature/libvgm-visualisation`，从 `333b66a` 到 `abbb46a`。同一个函数
> (`KeyboardRowPaint` 的波形绘制) 被改了四次，每次都是对的，每次都不够。

## 1. 四次反馈，四个"不对"

| 反馈 | 我改了什么 | 结果 |
|---|---|---|
| C140 波形"像包络" | 加 `cycleBytes`，只画一个周期 | **周期画出来了**，但看不到样本全貌 |
| "无法展示整个采样的全貌" | 去掉周期，整段压进 128 列（min/max 填充） | **采样对了**，合成波形变成斜线 |
| "合成类应该阶梯，不是连线" | 加回 `buildStepPath`，按"有没有 `wave`"分 | **合成对了**，N163 还是斜线 |
| "N163 好像没改过来" | 判据改成 `sampleRate > 0` | 对了 |

## 2. 根因：四次都在问"存在"，一次都没问"语义"

前三次的判据分别是：

```
1. cycleBytes > 0 ?        一个周期 : 整段
2. wave 非空 ?             填充     : 阶梯
3. wave 非空 ?             填充     : 阶梯      ← 和 2 一样，只是加了 buildStepPath
```

**三个都在问"有没有某个东西"。**

而真正决定画法的问题是：**这一列代表的是一段时间，还是一个瞬间？**

| 数据 | 一个点的含义 | 形状 |
|---|---|---|
| 合成（`cycleFor`） | 一个采样周期内的电平 | **阶梯** — 保持，然后跳 |
| 波表（FDS 64 点、N163 ≤256 点） | 同上，只是存在内存里 | **阶梯** |
| 录制（DPCM、C140） | 一个采样点的电平，几千个 | **填充带** — 每列是若干采样的范围 |

**波表和合成是同一种东西**，只是一份来自内存、一份由算术生成。**这就是为什么按"有没有 `wave`"分会漏掉 N163** —— 它有 `wave`，但它的 `wave` 是波表，不是录音。

## 3. 为什么第三次改完时我以为对了

`buildStepPath` 加回去了，`wave` 非空的走填充 —— **在 NES 的 DPCM 和 C140 上都是对的**。

**而 N163 在 NSF 那条路上**（`NsfPlayer`），我验的时候看的是 libvgm 的曲子。

**教训**：这一支有两条后端（NSF 和 libvgm），**每一条都有自己的采样/波表组合**。改一个横跨两者的函数，只在一条后端上验证，等于没验。

## 4. 最终判据

```cpp
const bool recorded = channel.sampleRate > 0.0f;

if (recorded && values.size () > kDisplayPoints)   // 填充带
else                                               // 阶梯
```

**两个条件缺一不可**：

- **`sampleRate > 0`** 是"这颗芯片播录制的字节"。只有解样本的芯片填它（`NesApuDecoder` 的 DPCM、`C140Decoder`、`NsfPlayer` 的 DPCM），**波表芯片一个都没填**。导出功能用的是同一个标志。
- **点数 > 128** 是"一个点装不满一列"的必要条件。**只有 8 个点的采样填充起来就是 8 根柱子** —— 那种情况下阶梯更诚实。

**长度不能单独用**：一段短的 DPCM 比 N163 的波表还短，**任何阈值都会错分类一个**。

## 5. 可复用的判断

**① 同一个函数被同一个维度改了三次，说明维度错了。**
前三次都在改"用什么条件判断"，而没改"判断的是什么"。**第四次不是改判据的写法，是换了一个判据。**

**② 问"有没有 X"之前，先问"X 是什么"。**
`wave` 非空能告诉你有数据，**不能告诉你是哪种数据**。而这一支里，`wave` 至少有三种来源：DPCM 录音、FDS 波表、N163 波表 —— **后两种和第一种要相反的画法**。

**③ 改横跨两条后端的代码，两条都要看。**
这一支的 NSF 和 libvgm 是两套独立的采集，**波表只出现在 NSF 那边**，所以只在 libvgm 上验会完全看不到 N163。

**④ 用户报"某个通道不对"时，先找它和别的通道在数据上差什么。**
"N163 不对" 的答案不是画法错了，是 **N163 有 `wave` 但它的 `wave` 是波表** —— 一个数据来源上的差别，不是绘制上的。

## 6. 注释位置

| 位置 | 写了什么 |

| `ui/KeyboardRowPaint.cpp` 的 `paintWave` | 两种形状、判据为什么是 `sampleRate` 而不是长度、为什么波表填充会塌成一像素线 |
| `ui/KeyboardRowPaint.cpp` 的 `buildStepPath` | 为什么阶梯和图线不同（硬件保持一个周期再跳） |

## 7. 没做的事

- **没有绘制测试**。三次返工都是靠眼睛发现的，套件里一行都不画。按 `code-quality.md` §7.5，这是有意的分工（界面用眼睛），但代价是**同一处能被改坏三次**。
- **`cycleBytes` 已被删除**（`dba8d5a`）。它服务于第一版"只画一个周期"，而那版被推翻了。**字段留下了一次提交的垃圾**，删它的提交说明里写了原因。
