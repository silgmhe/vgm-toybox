# 画了，但看不见

> 三个通道报"波形是直线"。两处 bug，一处让波形画出来只有 0.3% 的幅度，
> 另一处让样本根本没被导出。它们在报告里是同一个现象，在代码里隔了两个文件。

## 1. 现象

`test_file/K054539` 里的两首曲子：

| 曲子 | 通道 | 听到的 | 看到的 |
|---|---|---|---|
| `13 Please.. Rescue` | Ch 4 | 踩镲 | 直线 |
| `04 They Come From Hell` | Ch 1、Ch 2 | 鼓组 | 直线 |

**关键细节**：**独奏这个通道，声音是对的。** 所以字节、地址、长度都对，只有画法错。

**"画了但看不见"和"完全没画"是两种故障。** 前者 `wave` 非空、长度正确、渲染流程完整，只是数值小到看不出来；后者 `wave` 是 `nullptr`，走的是占位分支。**外观都能被描述成"没有波形"，但原因完全相反。**

## 2. 一次诊断，条件对了

前两次诊断失败的原因都写在 `2026-11-02-eight-guesses-before-a-wrapped-window.md`：条件写窄了，抓不到目标行。

这次只打一行：

```
KEY ch=3 start=0x006A82 type=0x08 units=2408 pitch=0x00FFFD bytes=2D 00 21 01 DD 12 31 D2
```

**`type=0x08` 一眼就是 4 位 DPCM**（`0x00` 8 位 / `0x04` 16 位 / `0x08` 4 位）。

**这条打印放在过滤之前**，所以每个 key-on 都会出现，不会被"这个不算样本"提前挡掉。**上一轮我把打印放在过滤之后，于是 ch=3 从未出现在日志里，看上去像"这个通道没被用过"。**

## 3. 两个 bug

### ① 显示的除数是错的

```cpp
// 错
(*wave)[i] = (float) (accumulator / 32768.0);
```

`32768` 是 **16 位 PCM 的满量程**。而 4 位 DPCM 的增量表最大一步是 `64`，一段普通样本累加后也就几百：

```
普通 4 位样本的累加范围   ±200 ～ ±600
除以 32768 之后           ±0.006 ～ ±0.018
```

**0.3% 到 1.8% 的幅度，画在行高一百多像素的格子里，就是贴着中线的一条细线。**

**修法**：按样本自身峰值归一化。

```cpp
// 对
float peak = 1.0f;
for (...) { peak = max (peak, abs (wave[i])); }
for (float& level : *wave) { level /= peak; }
```

### ② 导出整个跳过了

```cpp
// 错
if (isFourBit (voice.type) || voice.pitch == 0) { return; }
```

理由是"`SampleFormat` 里没有增量的位置"——**那个理由在半天前就已经不成立了**：`SampleFormat` 刚为 16 位 PCM 加过一个值。**一个"格式没有对应值"的判断，在另一颗芯片已经扩展过枚举之后，就只是没想起来而已。**

**修法**：加 `SampleFormat::dpcm4`，低 nibble 先，累加，峰值归一化。

## 4. 我自己引入的第三个错

第一版修导出时：

```cpp
// 错：以为 units 是 nibble 数
const std::size_t bytes = isFourBit (hit.type) ? ((hit.units + 1) / 2) : ...;
```

**但 `unitsOf` 在每种格式下都按字节走**（两个 nibble 共享一个字节，结束标记 `0x88` 也是字节级的），所以 **`units` 本来就已经是字节数**。

`2408` 字节被当成 `2408` 个 nibble，除以 2 得到 `1204`，**导出半个样本**。

**这个错不会让文件"看起来坏"**——它会正常播放，只是**提前结束**。听起来像"样本被截断了"，不像"算错了"。

**抓它的是断言**：八字节的 nibble 应该是**十六个电平**，不是八个。

## 5. 为什么这次一次就找到

| | C352 的空白行 | 这次 |
|---|---|---|
| 猜测次数 | **8 次** | **1 次** |
| 诊断条件 | 5 次写窄了 | 打印**所有** key-on，放在过滤之前 |
| 关键信息 | 从没打印过 `start`/`end` | 第一条就有 `type` |
| 用户的描述 | "像低频正弦" → 定位 noise | "独奏是踩镲" → 定位鼓组 |

**两次都靠用户的一句话收窄了范围。** 差别在于诊断：**这次的条件和打印位置一上来就是对的**，所以第一个数据就够。

**上一轮的教训是"诊断条件比诊断位置更容易写错"。** 这次条件是"每个 key-on 都打"，**没有条件可写错**。

## 6. 可复用的判断

**① 波形非空但看不出形状，先怀疑量纲，不要怀疑数据。**
幅度在 ±2% 以内 = 归一化除数错。**这种故障不会报错，`wave` 长度也对，只有画出来不对。**

**② 同一类数据在两颗芯片上用两套代码，迟早会不一致。**
K053260 的 KADPCM 一开始就用了峰值归一化——**因为它的表里有 `-128`，除 32768 会削波**。K054539 的 4 位表最大只有 `64`，除 32768 不削波，只是看不见。**两次都"没报错"，但一次结果对、一次结果错。**

**③ 改了单位语义，立刻重新核对所有用到它的地方。**
`units` 从"nibble 数"变成"字节数"只影响一行，但那一行决定导出多长。**断言应该数电平，不该数字节**——字节数是流程量，电平数才是用户看到的东西。

**④ 打印要放在过滤之前。**
过滤之后的日志只说明"通过过滤的有哪些"，**不说明被过滤掉的有哪些、为什么**。`ch=3` 从日志里消失的那一轮，我差点得出"这个通道没被用过"的结论。

## 7. 代码里的注释

| 位置 | 写了什么 |
|---|---|
| `chips/K054539Decoder.cpp` 的 4 位分支 | 为什么按峰值归一化，以及除 32768 的后果（"drawn, but nothing scaled to be seen"） |
| `backends/libvgm/SampleCollector.h` 的 `dpcm4` | 低 nibble 先、累加、归一化 |
| `backends/libvgm/SampleCollector.cpp` 的 `dpcm4` 分支 | 表来自 `k054539.c`；为什么是第二份表（解码器那份是私有的） |
| `backends/libvgm/K054539Samples.cpp` 的 `bytes` | 扫描按字节走，`units` 已是字节数，除 2 会导出半个样本 |
| `backends/libvgm/K054539Samples.cpp` 的 `sampleFormatFor` | 三种格式各对应哪个 `SampleFormat` |

## 8. 留下的同类缺口

**K053260 的 KADPCM 导出仍然缺失**，而且**不能复用 `dpcm4`**：

```
kKadpcmTable  第 8 项是 -128     ← 需要削波保护
kDpcmTable    第 8 项是   0      ← 不需要
```

**同一个"4 位增量"，两张表，两种数值行为。** 一个通用的 `dpcm4` 会掩盖这个差别，所以这里选择留缺口而不是合并。
