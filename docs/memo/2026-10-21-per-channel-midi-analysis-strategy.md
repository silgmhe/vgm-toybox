# 2026-10-21 每个 Mixer 通道可选 MIDI 分析策略：寄存器流 vs 音频频谱（暂不做）

## 结论

**现在不做。** 记下来，作为 Settings → MIDI 输出 / mixer 通道条上的一项未来功能：**每个 mixer 通道可以单独选择“MIDI 分析策略”**，两种模式——

- **A. 寄存器流分析（现状，默认）**：芯片解码器（`IChipDecoder`）+ `NoteExtractor`，按寄存器语义判断发声、门、音高；音高来自步进/分频/采样周期；
- **B. 音频频谱分析**：拿**该通道单独渲染出来的音频**做实时/离线音高与起音检测，直接产出 MIDI 音符，完全不懂寄存器。

两种模式并存、按通道选，而不是全局二选一。

## 为什么需要 B（一个具体的失败案例，不是假想）

《KOF'98 Stage 1》（`test_file/neo_geo/04 Stage 1.vgz`）1:39–2:09 的 Sax 独奏，ADPCM-B 的真实用法是**流式播放**：

| 观察 | 数值 |
|---|---|
| 30 秒内键开次数 | 1,898 次（约 63 次/秒） |
| 每次采样窗口 | `0x6A8D00` / `0x6B9000` / `0x6C9300` / `0x6D9600`，长度恒为 66,303 字节 |
| `DELTA-N` | 34,796…52,074，相邻比值约 1–2 个半音（音程就在这个寄存器里） |

也就是说：**驱动把一段 sax 录音切成 16 ms 的片、靠不断重启来播放，音高写在 `DELTA-N`**。于是“从 ROM 测周期”这条路天然测不到：该速率下一个周期约两万个 nibble，而每次只有一小片，相关器只能锁到 54 kHz 的共振峰（细节见 `docs/desgin/midi-output-design.md` 的 ADPCM-B 决策记录）。

寄存器流分析在这里还有两个结构性弱点：

1. **音高不在采样里，而在播放速率里**——需要“根音 + 比值”才成立，参考根音是策略问题（见下面待定项）；
2. **软件混音 / 整曲一个 sample 的驱动**（如 `test_file/ymz280b/`，整首曲子当一个 sample 放）根本没有 per-note 的寄存器事件，寄存器流只能输出“整曲一个音符”。

而这两种情况，**音频频谱分析都能给出音符**：信号里有真实的基频与起音。

## 设计草案（未实现，仅供将来开工）

### 数据通路

- 现状：`MidiSequenceBuilder` 在**离线**阶段把整条寄存器流喂给解码器，得到 `ExtractedPerformance`；
- 模式 B 需要**该通道的音频**：libvgm 已经支持按 track 静音（`[8]`/`[13]` 的 solo 与 mute-others 就是用它做的），所以可以做一次“只留该通道”的渲染 → 单通道音频 → 分析；
- 分析本身离线做（与现有 builder 同为离线阶段），实时只是“把分析结果当事件流播放”，不要求分析线程跟音频线程同步。

### 分析器

- 起音：能量包络 + 自适应阈值（或谱通量）；
- 音高：YIN / 自相关（复用 `chips/Pitch.h` 的思路，但输入是音频而不是 ROM 字节），带**八度纠错**——这正是当年 `estimateCycleLength()` 踩过的坑（平滑起音被当成最短周期）；
- 鼓判定：无稳定基频 / 起音后能量快速衰减 → C4 触发（与现有 `Family::adpcmDrum` 约定一致）；
- 参数：分析窗（≈2048）、hop、最短音符长度、音高置信度阈值。

### 设置项（放哪）

- 全局默认：Settings → MIDI 输出（§11.1 已经预留了 `ADPCM-B 的根音/采样率覆盖，或切换为 melodic` 这一格）；
- 覆盖：**mixer 通道条**上每通道一个下拉（Auto / Register / Spectrum / Off）。Auto 就是“寄存器流能报音符就用 A，否则用 B”，但 Auto 的判定规则要谨慎（不要变成不可预测的魔法）。

### 待定问题（开工前必须回答）

1. **成本**：模式 B 需要额外一次（或多次）整曲渲染；一首 3 分钟的曲子 44.1 kHz 单通道约 8 MB 浮点，可接受，但要确认“只在需要时渲染”；
2. **音准与延迟**：频谱法的音高精度（cents）与起音延迟（几十 ms）都要标在 UI 上，不能假装跟寄存器法一样准；
3. **与 `[13]` 的关系**：现有断言是“有声音的轨道必须报音符”，模式 B 天然满足；但“音符落在正确时间”需要新的断言（例如 `[13]` 对模式 B 通道只做“音符密度/时长”检查）；
4. **MIDI 通道分配**：一个 mixer 通道仍然只占一个 MIDI 通道，模式 B 不改变路由；
5. **ADPCM-B 的根音**：如果先做“根音 + `12*log2(delta/deltaRef)`”的轻量方案（模式 A 的补丁），要先定参考 `delta` 的取法（首个 / 众数 / 固定常量），这条与模式 B 独立。

## 重启条件

1. 用户明确要在 DAW 里“听到”某首曲子的 sax/人声旋律（而不是看到一片 C4 触发）；
2. 或者遇到第二首**软件混音/整曲一个 sample**、寄存器流无音符的曲目（YMZ280B 已经是一例）；
3. 或者 Settings → MIDI 输出子面板开工时，把这一项作为子面板里的一格一起做。
