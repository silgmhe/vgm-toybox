# 联动设备与通道编号：一次串音事故的记录

日期：2026-10-25
分支：`fix/polish`（修复）、`fix/linked-device-voices`（后续结构改造）

## 1. 现象

一首 YM2610 的 VGM（Metal Slug X - Back to the China）在混音器里 solo **FM 2 / FM 3**，
仍能听到别的声部：一部分像采样（被描述为 DPCM），外加一层底噪。其他曲目听不出。

## 2. 根因

YM2610 在 libvgm 里是**一个主设备 + 一个联动设备**：

```
主设备  YM2610   13 通道（6 FM + 6 ADPCM-A + 1 ADPCM-B）
联动    SSG       3 通道（AY-3-8910 兼容：3 方波 + 噪声 + 包络）
```

我们的轨道表只列主设备的 13 条；SSG 没有推子。

libvgm 的静音掩码分两半，`VGMPlayer::RefreshMuting()` 把 `chnMute[0]` 给主设备、
`chnMute[1]` 给联动设备。`singleChannelMuteOptions()` 把**同一个掩码写进两半**：

```
轨道 FM 2 → 掩码 = 除 bit 2 外全 1
  主设备：只剩 FM 2   ✓
  SSG  ：只剩它自己的第 3 个通道（bit 2）  ✗ ← 串音
```

FM 1/2/3 分别漏出 SSG 的 1/2/3 通道；FM 4-6 与 ADPCM 轨道因为 bit ≥ 3 全被置 1，
反而把 SSG 三个通道都哑掉了——这正是"只有 FM 2、FM 3 出问题"的形状。

引入提交：`cbaf588`（2026-10-20，标题为 **refactor**: split the VGM MIDI decoders…）。
它把掩码从"按半计算"改成"两半同值"，理由写在注释里：OPL4 的联动 OPL3 是 FM 半边，
通道 n 确实等于主设备的 n。方向对，**范围错**——只验证了 OPL4。
该提交未进入任何 tag（`v0.5.0` 发布于 10-19，早于它），所以"以前没有这个问题"成立。

## 3. 证据（逐轨独奏 RMS，问题曲目）

| 轨道 | 修复前 | 修复后 | 变化 |
|---|---|---|---|
| FM 2（t≈20 s） | 0.01309 | 0.00891 | −32% |
| FM 3（t≈5 s） | 0.03026 | 0.02771 | −8.4% |

其余轨道不变；全部静音时 RMS = 0。工具：`vgm_mixer_test <file> --tracks --at <秒>`。

## 4. 为什么测试没抓到

`[3]` 的断言是"各轨等增益求和 ≈ 直通混音（< 0.5 dB）"。这次漏出的 SSG 只占总能量约
**0.16%（≈0.01 dB）**——容差比缺陷大 50 倍，等于没有断言。

## 5. 影响面：还有谁会中

`libvgm` 全部 `DEV_DEF` 里带联动设备的只有 5 个定义（4 颗芯片）：

| 主设备 | 主通道 | 联动设备 | 联动通道 | 联动语义 | 本缺陷 |
|---|---|---|---|---|---|
| YM2203 | 3 | SSG | 3 | 独立声部 | **同样存在**（每个 FM 轨漏一个 SSG 通道） |
| YM2608 | 13 | SSG | 3 | 独立声部 | **同样存在**（漏进轨道 0-2） |
| YM2610 / 2610B | 13 | SSG | 3 | 独立声部 | 已修（`3666824`） |
| YMF278B（OPL4） | 24 | OPL3 | 23 | **镜像**（声音实际在联动设备上） | 不受影响 |

结论：

- 这不是 YM2610 独有的问题，凡是"联动设备有自己的编号、且没有独立轨道"的芯片都会中——
  即 **YM2203 与 YM2608 现在仍然会漏**（当前修复以 `DEVID_YM2610` 为条件）。
- OPL4 方向相反：把联动设备静音会让整颗芯片哑掉（实测 `mixer rms 0.0318 → 0.0000`），
  所以不能"一律挂起联动设备"。

## 6. 判定规则

> **当联动设备的通道编号与主设备不一一对应时，同一个掩码不能同时用于两半。**
> 对应（镜像）→ 两半同掩码；
> 不对应（独立声部）→ 掩码只写给拥有该通道的那一半，另一半整段静音或挂起。

## 7. 修复方向（本分支的工作）

1. **策略表**取代 `DEVID_YM2610` 特判：按联动设备的**类型**判断
   （SSG → 独立声部；OPL3 → 镜像），不再按芯片枚举。
2. **联动设备成轨**：`extraVoices` 的联动设备把通道追加到轨道表末尾
   （YM2610：13→16，既有索引不变，已保存工程的推子/静音不会错位），
   命名 `SSG 1..3`，组名仍为芯片名。
3. **掩码按半边计算**：链内唯一 `channelIndex` + 主设备通道数 → 决定写哪一半。
4. **MIDI 解码**：为 SSG 写寄存器解码（AY-3-8910 端口 0/1 → 音高/包络/噪声），
   让三条新轨有音符、能出 MIDI。
5. **测试**：YM2610 轨道数 16、每条 SSG 轨只在自己的通道发声时有能量、
   OPL4 保持 24 轨且等增益求和通过（防回归守门员）。
