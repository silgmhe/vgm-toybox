# MSM5232：一张键盘 ROM，和四个方波加起来

> 第九颗。它把“波表芯片”这个词的第三种形态补齐了：VSU 是寄存器写进 RAM 的表，Mikey 是
> 没有表的 LFSR，而这一颗是**查键索引 + 抽头求和**——没有表可读，也没有状态机可走，
> 波形是把四个方波按位相加算出来的。

## 1. 芯片事实

| 项 | 事实 | 出处 |
|---|---|---|
| 声部 | 8（2 组 × 4） | `msm5232.c:64` |
| 音高 | 低七位是**八十八项 ROM 的键索引**，`note = 21 + index` | `msm5232.c:35`、`290` |
| 噪声 | `value >= 0xD8` | `msm5232.c:290` |
| 波形 | 四个抽头方波之和：16'、8'、4'、2'，同相位、逐级高二倍频 | `msm5232.c:305-320` |
| 使能 | 组控制 `0x0C`/`0x0D` 低四位 | `msm5232.c:620-650` |
| 周期 | `2^(divider+1)` 拍，divider = ROM 条目 bit 9-11 | `msm5232.c:310` |
| 时钟 | 头部**没有**这一项；用芯片标称 2 119 040 | 实测 7 首皆无 |

**八十八项正好是 A0..C8**，所以索引就是键，音高不需要测量也不需要拟合：

```
index 0 = A0 = 21，index 48 = A4 = 440 Hz（断言里钉住了这一条）
```

## 2. 波形是加法，不是查表

```
tapBits = { n, n-1, n-2, n-3 }          // n = divider，floored at 0
level(t) = Σ_{已使能的 tap} ((t >> tapBits[tap]) & 1) ? +1 : -1
period   = 2^(n+1) ticks
```

四个抽头取自**同一个计数器的相邻位**，所以天然同相位——这也是它能画成一个稳定形状的前提。
开一个抽头是 50% 方波；开四个得到四级、256 点的阶梯。这些曲子用 `0x23/0x2E/0x2F/0x3F` 等组合，
多数时候同时开多个。

**组控制是“有没有声音”的开关，不只是音色**：一个 tap 都没开时，`EN_outX = 0`，整个组静音，
与声部是否 key-on 无关。行里的 `gate` 因此写成 `keyed && enabled != 0`，否则会把一个静音组
画成正在发声。

## 3. 唯一一次返工：手抄的表

第一版我把 88 项 `ROM(counter, bindiv)` 手写成了 16 进制常量，**全错**。正确做法是让机器生成：

```powershell
# 从 msm5232.c 的文本里取出 ROM(a, b)，按 a | (b << 9) 打包
[regex]::Matches($src, 'ROM\((\d+),\s*(\d+)\)')
```

生成后逐项与核心一致，并且 divider 的分布（索引 0..12 是 7，之后逐段下降）和“越到高音越低”
的直觉吻合，可以直接看出手抄版是错的。

**教训**：**只要数据在仓库里已经有一份，就不要手工复制到第二处**——要么引用，要么脚本生成并
在注释里写明来源。手抄的错误不会报错，只会让所有音高差几个半音。

## 4. 导出的语义

```
state.wave       = 一个周期的阶梯（4..256 点，电平 -4..+4）
state.sampleRate = hz × 点数        // 一拍一次，一个周期 2^(n+1) 拍
state.tableWave  = true             // 走波表路径：量化 + 单周期标记（§9.11.1 的教训）
```

导出按**形状内容**去重：同一阶梯在不同音高上只留一个文件，速率取最后一次。采样率保持绝对刻度
（除以 4），所以只开一个抽头的方波确实比四级阶梯轻——归一化会抹掉这个差别。

## 5. 验收

```
7 首 / 75 个样本；零样本曲目 0；点数 4..256
rate / 点数 = hz 逐行成立：9956.1/64 = 155.6，13289.8/8 = 1661.2
46/46 + 新增断言 testMsm5232Shape PASS
用户听感确认：导出的波表正确
```

**这次没有做全曲集合比对。** `03 Main BGM` 是 1:47，按 1.5 秒采样只覆盖前 30 秒：行里出现 18 个
(点数, 速率) 组合，导出 23 个，其中 6 个在这一窗口内命中，其余在这些时刻没被采到。**这是抽样，
不是全曲覆盖**——真正把两边钉死需要扫完整首（约 70 次探针），这次按用户的听感确认收尾，记为
后续可补的验证，而不是当作已完成的证据。

## 6. 三颗波表芯片的对照（可以当下一个的判据）

| 芯片 | 波形从哪来 | 一个周期是什么 | 关键判据 |
|---|---|---|---|
| VSU | 寄存器写进 RAM 的表 | 32 个六位条目 | 地址高位区分表与寄存器 |
| K005289 | `0xC3` 数据块的 PROM | 32 个四位条目 | RAM 块、16 位地址 |
| Mikey | 12 位 LFSR 递推 | 周期 = LFSR 循环长度 | 没有周期时不能回放旧波 |
| **MSM5232** | **键索引 + 抽头求和** | **`2^(divider+1)` 拍** | **组控制决定有没有声音** |

**下一颗（YMZ280B / OPN-ADPCM / SegaPCM）回到采样类**，判据换成“样本长度从哪来、用什么格式解码、
速率由谁决定”，前四颗的经验值不大，但 `tableWave` 的反面教训（采样别被当波表）同样适用。

## 7. 已知简化

- `volume` 恒为满：这一颗的音量在电容积分上，没有可读字段；`0x08..0x0B` 的起音/衰减、
  `0x10..0x1A` 的每路输出音量都未参与
- 索引 > 0x57 被钳到 0x57（与核心一致），所以 88..95 这几首里出现的高索引都按 87 处理
