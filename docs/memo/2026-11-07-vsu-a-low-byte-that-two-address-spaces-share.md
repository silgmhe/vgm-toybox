# VSU：两个地址空间共用一个低字节

> 第六颗、也是**第一颗没有 ROM** 的波表芯片（Virtual Boy，`vsu.c`）。
> 波形是寄存器写进 RAM 的，所以这一颗的难点从头到尾都在**地址**上，不在数据格式上。

## 1. 芯片事实

| 项 | 事实 | 出处 |
|---|---|---|
| 声道 | 6，第 6 个是 LFSR 噪声（无波形） | `vsu.c:379-386` |
| 波表 | 5 张 × 32 个条目 × **6 位** | `vsu.c:116`、`229` |
| 中点 | **0x20**：播放时 `WD -= 0x20` | `vsu.c:402` |
| 表选择 | **寄存器 0x6**，`RAMAddress = V & 0xF`；>4 播放静音 | `vsu.c:358`、`383` |
| 频率 | 11 位，`2048 - freq` 个时钟走一格 | `vsu.c:266`、`302-322` |
| 时钟 | VGM 头 **0xC4**，实测 5 000 000 | `_CHIPCLK_OFS` |
| 地址 | `A <<= 2; A &= 0x7FF`：`< 0x280` 波形、`< 0x400` 调制、`< 0x600` 寄存器 | `vsu.c:213-238` |
| VGM 命令 | `0xC7`，**大端 16 位偏移 + 数据** | `Cmd_Ofs16_Data8` |

换算回 VGM 偏移空间：`< 0x100` 是波形 RAM（5×32 连续排列），`0x100..0x17F` 是声道寄存器
（`0x100 + ch*0x10 + reg`），`0xA0..0xFF` 是调制表。

**实测**（`03 Title`）：波形写 228 次、寄存器写 2574 次，**首个波形写在第 208 字节**——全部
上传都在第一个 key-on 之前，这与核心的规则一致：任一 voice 播放中时波形写会被丢弃
（`vsu.c:222-228`），所以表在播放期间是静态的。

## 2. 唯一的坑：一个低字节，两个空间

这是本轮最值得记的一件事，因为它**不是新芯片引入的缺陷，而是既有的静默错误被这次改动暴露**。

```
VGM 偏移 0x010  → 波形表 0 的第 16 个条目
VGM 偏移 0x110  → 声道 1 的控制寄存器（IntlControl）
两者 & 0xFF 都是 0x10
```

旧读取器只保留低字节，于是**波形上传被当成控制寄存器写**：一个值为 `0x89` 的波形字节会把
声道 1 的 bit7 置起来——一次上传就能“点亮”一个声部。它不报错、不崩溃，只是让状态悄悄变脏。

修法必须三段齐全，缺一段都不成立：

| 层 | 改动 | 缺了会怎样 |
|---|---|---|
| 读取器 | 偏移 bit 8 → `VgmCommand::data2` | 信息在源头就没了 |
| 加载器 | `data2` → `RegisterWrite.port`（0 波形 / 1 寄存器） | 解码器分不清两半 |
| 路由器 | 把 `port` 传给 `VsuDecoder` | **行全空、音高全灭** |

第三段是我漏掉的：IR 里已经带了 port，路由的 `case vsu` 却没往下传（它的 `queue` 调用没有
第五个参数）。表现是**所有行突然变成 `wave=null, rate=0, note=-1`**。

**这次“行突然全空”反而是好事**：如果从一开始就没有波形，我会以为“VSU 还没做完”；而行从有
到无，把问题直接指到了写入通路上。**能失败的可见状态比不可见的正确更有用。**

## 3. 导出的是“一个周期”

一颗波表芯片没有“采样长度”这回事：32 个条目就是整张波，播放时循环。所以：

```
state.wave      = 32 个点，(entry - 0x20) / 32
state.sampleRate = clock / (2048 - freq)      // 每秒走多少条目
hz              = rate / 32                   // 与既有的音高公式一致
```

拖出来的文件在这个音高上正是无缝循环——这也是波表芯片与采样芯片在导出语义上的区别。

**去重按内容哈希**：同一张表会在不同音高上反复使用，而两个段落也可能重写同一张表。以 32 字节
的哈希作键，前者合成一个文件，后者分开——与位置无关，只与“是不是同一个波”有关。

## 4. 验收

```
03 Title：全曲每 0.5 秒扫一遍行，4 个导出项的 (32 点, 速率) 4/4 命中
30 首 / 87 个样本，单曲 1–5 个；速率 2495 – 53191.5 Hz；零样本曲目 0
```

**断言**：`testVsuWave` —— 32 点、`0x20` = 0、`0x3F` ≈ +0.97、`0x00` = −1、速率
`5000000/1792 = 2790.18`、`hz = 87.19`；以及**波形写不会 key-on**（这正是 port 拆分要防的事）。

**顺带修了一处旧测试**：`testVsuNotes` 原来直接构造寄存器写入而不设 port，拆分后它们会落到
波形半区（于是“a VSU key write is one note”失败）。补上 `write.port = 1` 并注明原因。

## 5. 已知限制

- **噪声声道无波形**：第 6 个声道是 LFSR，`wave = null`、`rate = 0`，行按打击乐处理。
- **不模拟包络/扫频对速率的影响**：核心的 `EffFreq` 会随 sweep 改变，行与导出用的是寄存器值。
  这一颗的驱动在音符期间不改 freq，实测行与导出一致。
- **调制表不画**：`0xA0..0xFF` 的调制波形没有对应的声道，跳过。
