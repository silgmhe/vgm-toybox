# 让阶梯活下来：采样导出的时间轴（2026-11-10）

**一句话**：拖进 DAW 变闷不是位深的问题，是**重采样**；修法是**按目标速率写、把保持烘进文件**，而不是让宿主替我们插值。

## 一、先排除的两个误判

- **“32 位工程会重采样”**——位深不是原因。8 位到 float32 是精确的，我们的 WAV 本来也是 float32（`WaveExport.cpp` 的 `writeFloat32Wav`）。
- **“8 位量化丢了高频”**——量化噪声两种写法都在，它没有消失。

真正发生的事：文件头写的是**芯片读字节的速率**（DAC 8–23 kHz），工程的速率是 44.1/48 kHz，导入那一刻宿主做了一次**带限重采样**。

## 二、为什么高频一定丢

芯片的输出是**零阶保持**：写一个字节，电平保持到下一次写。它的频谱是 `sinc` 包络乘上一串位于 `rate × k ± f` 的镜像。

- 文件 23 105 Hz → Nyquist 11.55 kHz；镜像在 23 kHz 附近，**在文件带宽之外**，任何忠实的重采样都会把它们滤掉；
- 8 位 DAC 的“颗粒感”**就是这些镜像**，所以被滤掉以后不是“变干净”，是“变闷”；
- Furnace 里有，是因为它按样本逐点读出、输出端做保持（插值关），没有先带限到源速率。

## 三、实测（`02 Green Hill Zone`，三段）

| 段落 | 处理 | 平台占比 | \|dx\| | HF |
|---|---|---|---|---|
| 0x1516 @23 105 | 原样 | 0.050 | 0.107 | 0.030 |
| | 线性→44.1k | 0.025 | **0.051** | **0.012** |
| | 保持→44.1k | **0.502** | **0.078** | **0.021** |
| 0x0060 @7 981 | 原样 | 0.258 | 0.022 | 0.005 |
| | 线性→44.1k | 0.235 | **0.004** | **0.000** |
| | 保持→44.1k | **0.866** | **0.010** | **0.002** |

线性插值削 6–20 dB（sinc 更狠，所以这是保守估计）；保持版留下 50–87% 的平台。

## 四、做法

```
n = round(len × target / rate)
out[i] = in[(i × len) / n]        // 整数除法 = 零阶保持
```

- `heldAt()` 在 `WaveExport.cpp`，与波表的 `nearest()` 是同一条规则（“深度属于纵轴，保持属于横轴”）；
- `writeSamples()` / `writeSampleWav()` 接受 `targetRate`，0 表示保持芯片速率；**先按秒截断、再保持**，所以“最长 N 秒”仍是秒；
- 设置 `export.sampleRate`：`0` 跟随宿主（默认）、`-1` 芯片速率、`44100/48000/96000` 固定；
  插件用 `processor.getSampleRate()`，独立版用 `PlaybackEngine::outputSampleRate()`，未知时 44 100；
- **两条导出路径都走它**：File > Export 与拖拽。只改一条等于制造“同字节不同听感”的 bug。

## 五、这套做法的边界

1. **工程速率与目标速率不同时，宿主仍会转一次**，阶梯仍会被削——所以默认必须是“跟随宿主”；固定值只用于“导出去给别人用”。
2. **保持点数是整数**：8 kHz 的样本在 44.1k 上每字节 5.5 点，实际按 5/6 交替，抖动 ±0.5 点（11 µs）。听不出来，但它不是“精确的零阶保持”。
3. **文件变大**：14.8k→44.1k 是 3.0×，23.1k→44.1k 是 1.9×，8k→44.1k 是 5.5×。
4. **容器仍是 float32**：位深不参与这个问题；要 8/16/24 位整数是另一个需求。
5. **芯片速率仍保留**（`-1`）：对 tracker/采样器，“真相速率”才是对的，那不是这次的场景。

## 六、以后判断“导出听着不对”的三问

1. 文件头速率和工程速率**一样**吗？不一样就是宿主在转，先怀疑这里。
2. 目标是**记录**还是**演奏**？记录要芯片速率，演奏要工程速率。
3. 参照物是**同一段字节**吗？DAC 的同一记鼓在文件里可能存了两份（`0x0636` 与 `0x23F8` 完全相同），比错对象会得出错误结论。
