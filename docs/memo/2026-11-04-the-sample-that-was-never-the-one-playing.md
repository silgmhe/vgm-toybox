# 一块从未被听到的采样

> RF5C164 的 Ch5：导出是慢放的鼓，实际听到是钢琴。为此查了整整一个分支，改了速率、长度、
> 结束标记、bank 上传、地址映射，**每一次都有"决定性测量"支撑，每一次都被下一个测量推翻**。
> 最后一项测量（核心里按实例统计输出能量）显示：这颗芯片的输出恒为零。
>
> 本文记录搁置的现场：哪些是确凿的、哪些是我误判的、以及为什么这些误判会反复出现。
> 设计文档的覆盖表里这一行已改为**搁置**（`docs/desgin/libvgm-visualisation.md` §9.5）。

## 1. 现象

`test_file/RF5C164/01 - Palmtree Panic Zone Past.vgz`，Sonic CD，RF5C164，8 条轨道。

| 观察 | 数值 |
|---|---|
| Ch5 渲染（探针独奏） | 0.491 s，峰值 0.064，自相关 71.5 Hz |
| Ch5 导出（`0x8000` 槽位） | 5186 B @ 10442.7 Hz = 0.497 s |
| 导出内容的周期 | **12 字节（r=0.31，很弱）**，折算 870 Hz |
| 71.5 Hz 在 10442.7 B/s 下应有的周期 | **146 字节** |
| 用户听感 | 渲染像钢琴，导出像慢放/环绕的鼓 |

**12 字节与 146 字节之间差了 12 倍。** 长度和速率都对得上（0.497 vs 0.491，差 1%），
只有内容不对——这是整条线唯一始终成立的观察。

## 2. 确凿的部分

这些有直接读数或源码支撑，可以当作事实：

**VGM 命令格式**

- `0x67` 块解析正确：块头在 `0x80`，`type=0x02`，`size=158720`，块尾正好落在 `0x26C87`。
- `0x68` 是 **12 字节**：`68 66 02 | pos(3) | addr(3) | len(3)`。原始字节：

  ```
  68 66 02 00 00 00 00 00 00 00 10 00   → type 0x02, pos 0, addr 0x0000, len 4096
  68 66 02 00 00 00 00 10 00 00 10 00   → type 0x02, pos 0, addr 0x1000, len 4096
  ```

  类型在 **+2**（从 +1 读到的是 `0x66`，那正是块标记）。

**寄存器语义**

- `0x07` **bit6 置位**：低 3 位选通道。
- `0x07` **bit6 清零**：低 4 位是 RAM bank，所有写地址要 `|= bank << 12`。
  这是 libvgm `DoRAMOfsPatches` 的原文，并在运行时验证过：

  ```
  addr=0x0000 pos=5120 len=512   →   DoRAMOfsPatches 之后   addr=0x8000
  ```

- 速率公式 `step = freq × 2048 / 32552`，与 Sega CD 官方驱动
  `reference/SegaCDMode1PCM/cd/pcm-io.s` 的 `freq<<11 / 32552` 逐字一致。
- `PCM_ENV`/`PCM_PAN` 不写，通道静音（核心把输出乘 0）。

**两个芯片的差异**

- RF5C68A datasheet：**偏移二进制**（127 居中）。
- RF5C164（Sega CD 驱动 `pcm_s8_to_sm`）：**符号-幅值**（`0x80` 为零）。
- libvgm 的两个核心都按符号-幅值解码，所以对"播出来的声音"两者一致；
  差异只在"是否忠实于真实 RF5C68 硬件"。

**运行时的实际状态**

```
设备表 : 1 台 — vgmType=0x10 (RF5C164), core=0x47454E53 (GENS), 采样率 32552
         dacStreams = 0，daccontrol_* 从未被调用
芯片   : 9 个实例，按实例累计输出能量 —— 全部为 0
         全部实例 RAM[0x8000] = 80 80 80 80（符号-幅值的零）
我们的映像  : RAM[0x8000] = 99 19 83 97
引擎        : 0.491 s / 71.5 Hz / 峰值 0.063
```

## 3. 试过并失败的路

按时间顺序，每一条我都以为找到了根因。

| # | 改动 | 结果 | 为什么错 |
|---|---|---|---|
| 1 | 修正色率/字节率 | 数字变了，听感没变 | 基于被污染的逐通道测量（见 §4） |
| 2 | 长度取"首个音符门长" | 导出仍在，仍是鼓 | 门长是"响多久"，不是"数据多长" |
| 3 | 长度取"起点→第一个 `0xFF`" | **全部变成 8192 B** | 这首曲子的六个槽位里**没有 `0xFF`**；那是自制驱动的规则 |
| 4 | `pcmBank` 应用 `0x68` 拷贝 | 导出列表形状变了 | 从未与仿真器对上，只是"变了" |
| 5 | bank 从 `0x6C00` 开始写（截断） | **7 个样本塌成 1 个** | 与"6 个通道同时有声"矛盾 |
| 6 | `0x68` 长度 12 → 11 | 无变化 | 问题在字段偏移，不在长度 |
| 7 | `Start()` 后把整块 bank 写进芯片 | `ok=1`，**渲染完全没变** | libvgm **本来就上传**了 bank，这是空操作 |
| 8 | 首次 `render()` 时上传 | **Ch3/Ch4 静音** | 覆盖了驱动用 `0xC1` 流进来的页 |
| 9 | 逐轨独奏 / 静音隔离 | 两条路径数字完全一样 | 一致性被误读成"隔离正确"，其实可能两者都没隔离 |
| 10 | 从芯片读回 64 KB 对比 | 全零 | `SCD_PCM_MemRead` 把偏移遮到 12 位，读到的是窗口首字节 |
| 11 | 按实例统计能量（GENS） | 全为 0 | 统计写在函数**开头**，测的是刚被清零的缓冲 |

**共同的失败模式**：改动本身都"有效果"（数字变了、列表变了），但我没有一条**验证条件**
能区分"变了"和"对了"。唯一一次有验证条件的是第 5 条——`ours[0x8073]` 必须等于芯片的 `8A`，
它通过了，却因为导出塌成 1 个文件而不得不放弃。

## 4. 测量方法上的错误（这是最有价值的部分）

这一支上我犯的测量错误比解决的问题多。**每一个都表现为一个"确定性结论"**：

| 错误 | 表现 | 真相 |
|---|---|---|
| 归一化错 | 核心输出 `peak 0.0000` | 核心不是 int32 满幅，`Data×MUL` 是几千量级 |
| 在清零缓冲上统计 | 所有实例能量为 0 | 统计写在 `memset` 之后、填充之前 |
| **共享 static 计数器** | 只打印了 `id=7` 一个播放器 | 成员函数里的 `static` 被 8 个实例共享 |
| 跨轮次比较 | "芯片静音、引擎有声" | 一次运行读芯片，另一次运行读引擎，被当成同一时刻 |
| 只看开头几条 | `0x07` 都是选通道 | 只筛了前 8 条，没统计全量 27493 条 |
| 窗口掩码 | 读回全零 | 12 位掩码，读到的是窗口首字节 |
| 漏写必需寄存器 | 校准输出 1e-7 | 缺 `0x01`/`0x00`，且必须先声像后包络 |
| 单位错位 | "周期 14 字节 → 71 Hz" | 用两个不同脚本算的两边，不可比 |

**教训：先校准测量工具，再用它得出结论。** 探针现在内置了握手校准——写一段
`0xC0/0x40` 交替的方波，必须读出 `-3776 3776 -3776 3776`（`(15×127)>>5 ×64`）。
**校准不过，探针无权说"芯片静音"。**

## 5. 仍未解释的悖论

```
唯一的设备  →  输出能量 0
DAC 流      →  不存在
其他设备    →  没有
引擎输出    →  0.491 s，71.5 Hz，峰值 0.063
```

四项里必有一项是错的，而我没有再往下测。**下一次的起点是这个**：在
`LibvgmTrackPlayer::render` 与 `SCD_PCM_Update` 里**同一个 block** 同时统计能量。

- 引擎侧有、芯片侧零 → 声音绕过芯片，整条"导出 vs 渲染"的对比链前提就错了
- 两侧都有 → 芯片统计仍有 bug，回到采样内容本身
