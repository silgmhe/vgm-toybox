# OPL3（YMF262）：波形、鼓行，以及四个要拍板的问题

> 2026-11-28。**调研，未写代码。**
>
> 用户的三个问题：① FM 行还是单周期；② `test_file/ymf262` 里的鼓行没有信号，是不是和别的通道复用了；③ 先把 FM 的完整波形做出来。

## 一、鼓行没有信号：**曲子没开节奏**（有数据）

三个测试文件里 **`0xBD` 的写入次数都是 0**（`0x5A` 和 `0x5B` 两个端口都查了）：

| 文件 | port0 `0xBD` | port1 `0xBD` |
|---|---|---|
| `155 Concert 1.vgz` | **0** | 0 |
| `156 Concert 2.vgz` | **0** | 0 |
| `157 Concert 3.vgz` | **0** | 0 |

**OPL3 的节奏模式（`0xBD` bit5）从未被打开**，所以那 5 行没有任何东西可画。

**但你的第二个猜测在原理上是对的**：OPL3 一旦开启节奏，会**借用 bank 0 的通道 6-8**（和 OPL2 一样），鼓的声音走的就是那三路。区别在于——**这批曲子里连开都没开**。

**所以我们现在的 UI 有个结构性问题**：`OplDecoder` 给 OPL3 声明了 **23 行**（18 旋律 + 5 节奏，`rhythmBase = 18`），而这 5 行在大多数 OPL3 曲子里永远是空的。**这是“看起来坏了、其实是没数据”的典型。**

## 二、单周期的原因：`capturePatch` 直接拒绝了 opl3

```1042:1042:plugin/Source/chips/OplDecoder.cpp
	if (channel < 0 || channel >= melodic || impl->variant == Variant::opl3)
```

**整个 OPL3 变体没有 patch 路径**，所以 18 行全部回退到合成的单周期。这不是遗漏某个寄存器，是**这条分支从来没写过**。

## 三、OPL3 比 OPL2 多出来的三件事

### ① `0xE0` 波形选择（**现在只存了一半**）

```689:695:plugin/Source/chips/OplDecoder.cpp
	if (reg >= 0xE0 && reg < 0xF6)
	{
		const int channel = modulatorChannel (reg);
		if (channel >= 0)
		{
			impl->channels[channel].waveform = (int) (write.value & 0x03);
		}
```

`modulatorChannel` 对**载波**返回 -1，所以**载波的波形被丢掉了**。OPL3 的四种波形（正弦/半正弦/绝对正弦/脉冲）主要由载波决定，**丢一半等于音色错一半**。数据结构要改成 per-operator（`opRegs` 那样 2 × 4 的旁边再加 2 个字节）。

### ② 第二 bank

`modulatorChannel` 已经带 `(twoBanks ? port*9 : 0)`，`capturePatch` 只要按通道号取值即可；`0xE0` 的地址仍按 `reg & 0x1F` 走偏移窗口，**port 在命令里、不在寄存器里**，这点和读寄存器一致。

### ③ 4-op 模式（**代码里 0 处处理**）

```bash
grep -c '0x104\|0x105\|4op' OplDecoder.cpp   →   0
```

OPL3 允许把通道配对成 4 算子声部（`0x104`/`0x105`）。**未处理时，一个 4-op 音色会被画成两个 2-op 声部**——形状是“半个音色”，但不会报错。这是本芯片最大的一个语义缺口。

### ④ 核支持情况（好消息）

`nukedopl3.c` **有节奏实现**：`:616` 的 “Rhythm mode”、`:740` 的 `OPL3_RhythmSetupAlg`。**所以如果某首 OPL3 曲子真的用了鼓，仿真核是能发声的**，缺的只是我们的可视化。

## 四、四个要拍板的问题

**D1 · 本次范围：只做 2-op，还是连 4-op 一起做？**

| 选项 | 含义 | 代价 |
|---|---|---|
| **A（建议）** | 2-op：18 个通道各自一条 patch（2 算子 × 4 bank + `0xE0` + `0xC0`） | 小，覆盖大多数曲子；**4-op 音色显示为两个 2-op**，注释里写明 |
| B | 同时支持 4-op 配对 | 中等偏大：要读 `0x104`/`0x105`，把两个通道合成一条 4-op 的 patch 渲染 |

**建议 A**：先把“不再画单周期”解决，4-op 作为独立一轮（否则这一轮范围会失控）。

**D2 · 载波波形必须补上（这不是选择题）**

`0xE0` 改成 per-operator。**不补就等于音色减半**，而且它只在 OPL3 上有意义，不会影响已完成的 OPL2/OPLL。

**D3 · 那 5 行节奏行怎么处理？**

| 选项 | 现象 |
|---|---|
| A | 保留 5 行，永远显示“无信号”（就是现在） |
| **B（建议）** | **只在曲子写过 `0xBD` 时才展示这 5 行**，否则不显示——用数据决定，而不是固定加 5 行 |
| C | 完全去掉 OPL3 的节奏行，鼓的声音按“借用 ch6-8”显示在那三行上 |

**建议 B**：它同时解决你现在的困惑（“为什么这几行一直没信号”）和未来的正确性。C 也可以，但会让鼓在 bank 0 的行上“冒充旋律”，更难读。

**D4 · 电平（`fmOutputBits`）必须实测，不能沿用 16**

YM3812 的 16 是从“混音里一个声部”推出来的，**OPL3 的核（`nukedopl3`）量级不同**（它是 16 位整数运算，与 AdLibEmu 的定点不同）。**按上次的教训：先量“最难的配置”，再定数字。**
