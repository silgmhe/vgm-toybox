# OPL2 的五个鼓行：还剩什么，以及一个会踩的坑

> 2026-11-24。**调研，未写代码。**
>
> OPL2（YM3812 / YM3526 / Y8950 的 FM 半）的**旋律部分已经完成**：九条算子寄存器成为 patch、
> `kOpl2Dialect`、`fmOutputBits = 16`（混音电平）、文件速率直渲、行名 `FM 1..9`。
>
> **剩下的只有 `Ch 10`–`Ch 14` 这五行**，它们仍在画通用正弦。

## 一、芯片事实（OPL2 的节奏）

与 OPLL 结构相同，寄存器不同：

| 项 | OPLL（已做） | **OPL2（本轮）** |
|---|---|---|
| 使能 + 触发 | `0x0E`：bit5 使能，bits 4-0 = BD/SD/TOM/CYM/HH | **`0xBD`**：bit5 使能，bits 4-0 同样是五个触发位 |
| 音色来源 | ROM 预置号（`0x36-0x38` 高四位） | **借用通道 6/7/8 的算子寄存器**（`0x20-0x35`、`0x40-0x55`、`0x60-0x75`、`0x80-0x95`） |
| 音量 | `0x36-0x38` 的低四位 | 同上算子的 **TL**（`0x40-0x55`） |
| 音高 | `0x16-0x18` / `0x26-0x28` | **BD/TOM 用 `0xA6/0xB6`、`0xA8/0xB8`**；HH/SD/CYM 固定 |

**槽位归属**（AdLibEmu 的 `operator_advance_drums` 调用点，`adlibemu_opl_inc.c:1439`）：

| 鼓 | 用到的槽 |
|---|---|
| **BD** | ch6 的调制器 + 载波（槽 12、15） |
| **SD** | ch7（槽 13、16） |
| **HH** | ch7 的调制器（槽 13） |
| **TOM** | ch8 的调制器（槽 14） |
| **CYM** | ch8 的载波（槽 17） |

**SD 与 HH 共用 ch7 的调制器**——这是真机行为，不是核的简化。

| 项 | 状态 |
|---|---|

## 三、一个会踩的坑（必须先承认）

```533:545:plugin/Source/chips/OplDecoder.cpp
			const int channel = reg - kBlockBase;
			if (impl->rhythmEnabled && channel >= 6)
			{
				return;		// borrowed by the rhythm instruments
			}
```

**节奏模式下 `0xB6-0xB8` 被直接丢弃。** 而 BD 和 TOM 的**音高就在 `0xB6` / `0xB8` 的 block 位里**。

**后果与 OPLL 那次一模一样**：patch 里缺 block → 鼓停在 block 0、fnum 0 → 渲染出的是**直流台阶**，
实测 `peak 0.0059`，看起来"没有声音"。**那一轮我花了两个提交才找到它。**

**所以本轮第一件事是把 `0xB6-0xB8` 的 block/fnum 也记下来**（新的 `rhythmRegs` 或复用通道字段），
否则鼓 patch 一定是错的。

## 四、要拍板的五件事

**D1 · patch 的内容**

| 选项 | 说明 |
|---|---|
| **A（建议）** | 该鼓用到的槽的算子寄存器 + `0xA6/0xB6`（BD）或 `0xA8/0xB8`（TOM）+ `0xBD` |
| B | 通道 6/7/8 的全部 24 条算子寄存器 + 上述 |

**建议 A**：只带该鼓真正用到的槽，patch 更小、也更容易对照。**代价**是要写一张"鼓 → 槽"的表
（五行）。

**D2 · 触发方言**

新增 `kOpl2RhythmDialect`（与 `kOpllRhythmDialect` 同形）：
`init` 写 `0xBD = 0x20`，`noteOn` 写 `0xBD = 0x20 | triggerMask`，`noteOff` 写回 `0x20`。
**建议照抄**，只换寄存器地址。`0xBD` 的 bit7/bit6 是 tremolo/vibrato 深度，保持 0。

**D3 · 长度与 trim**

OPLL 那轮实测：BD 包络约 41 ms，`lengthSeconds = 0.15`、`trim = 0.5`。
**建议先沿用这两个常数**，然后用一首 OPL2 曲子实测五个鼓的峰值再调——**先测，别照抄**。

**D4 · 是否带 `ym3526` / `y8950`**

它们用同一个 `0xBD`、同一套槽位 → **建议一起做**（free）。

**D5 · 面板长度**

AdLibEmu 每行 0.4 ms，**不需要** OPLL 那个 0.5 s 钳制；鼓本身只有 0.15 s，天然短。

## 五、工作量与顺序

| 步 | 内容 | 验证 |
|---|---|---|
| 0 | 补 `0xB6-0xB8` 的记录（BD/TOM 的 block） | 单元断言：写 `0xB6=0x0B` 后能读到 block |
| 1 | `capturePatch` 的 OPL2 节奏分支 + 「鼓→槽」表 | 断言：patch 的 oneShot/mask/寄存器数 |
| 2 | `kOpl2RhythmDialect` | 手工 patch 能出声 |
| 3 | 实测五个鼓的峰值与长度，定 `trim` / `lengthSeconds` | 数据进断言 |
| 4 | 面板 + 导出接通 | 截图 + 拖一行 |

**估：0–2 半天，3–4 半天。** 风险集中在第 0 步——**没有它，其余全是错的**。

## 六、留给下一颗的

`0x20` 的 bit5 在 OPL2 上是 **key-on/off 的另一种写法**（`0xBD` 之外还有 `0xB0`），
而 OPLL 的 `0x20` bit5 是 **sustain flag**——**同一个位在两族里意思不同，别照抄。**
